# 헬스장 플레이스 진단 도구

헬스장·피트니스 센터 전용 네이버 플레이스 진단 도구입니다.
**네이버가 순위를 매기는 3개 축(적합도 · 인기도 · 거리)** 구조로 진단하고,
목표 키워드가 실제로 매칭되는지 계산하며, 원하면 **현재 순위까지 추적**합니다.

개인 운영용입니다. 외부 공개나 상담 유도 기능은 없습니다.

## 화면 구조 — 대시보드형

매일 같은 자리를 눌러 쓰는 도구라, 소개 문구 없이 **들어오면 바로 숫자**가 나옵니다.

```
┌──────────┬──────────────────────────────────────────┐
│          │ 메인 / 대시보드      🔍 플레이스 주소 [수집] │  ← 상단: 주소 넣는 칸
│ MAIN     ├──────────────────────────────────────────┤
│ 대시보드  │ 스트롱짐 피트니스                          │  ← 가게 이름 + 현재 순위
│  한눈에   │ 강남역 헬스장 10위                         │
│  점수3축  │ ┌────┐┌────┐┌────┐┌────┐                │
│  할 일    │ │순위││리뷰││사진││소개│                  │  ← 큰 숫자 4개
│  개선기록 │ │10위││41개││12장││56자│                  │
│  기준22개 │ └────┘└────┘└────┘└────┘                │
│ 채우기 ●  │ ┌───────────────┐┌──────────────┐        │
│          │ │ 진단 점수 24점  ││ 할 일 19건    │        │  ← 왼쪽 분석 / 오른쪽 할 일
│ SETTING  │ │ 적합도 ████▁▁  ││ ① 소개글      │        │
│ 입력값    │ │ 인기도 ▁▁▁▁▁  ││ ② 대표키워드  │        │
│ 저장내역  │ │ 거리   ██▁▁▁▁  ││ ③ 편의시설    │        │
│ 이어쓰기  │ └───────────────┘└──────────────┘        │
│ 스트롱짐  │                                          │
└──────────┴──────────────────────────────────────────┘
```

- **왼쪽 메뉴** — 위쪽은 화면 전환(대시보드 / 채우기 도구), 아래쪽은 설정. 하위 항목을 누르면
  해당 칸으로 데려다줍니다. 맨 아래에 지금 보고 있는 가게 이름과 순위가 남습니다.
- **1000px 아래**(휴대폰·태블릿)에서는 왼쪽 메뉴가 **서랍**으로 접히고, 상단에
  **진단 / 채우기** 전환 버튼이 나옵니다. 서랍을 열지 않고 한 번에 바꿉니다.
- **한 번 수집한 가게는 다시 들어올 때 진단이 자동으로 돌아갑니다.** 버튼을 또 누를 필요 없이
  숫자부터 보입니다.
- 어두운 화면 설정(다크 모드)을 쓰면 그에 맞춰 바뀝니다.

### 두 화면 — 찾기와 채우기

한 번에 하나만 보입니다. 쓰는 시점이 다르기 때문입니다.

| 메뉴 | 무엇을 하나 | 안에 있는 것 |
|---|---|---|
| 🔍 **대시보드** | 지금 뭐가 비었나 찾는다 | 자동 수집 · 순위 조회 · 상위 3곳 비교 · 체크리스트 · 점수 · 먼저 할 3개 · 저장 내역 |
| ✍️ **채우기 도구** | 그 빈칸에 넣을 문장을 만든다 | 소개글 · 대표키워드 5개 · 리뷰 답글 3종 · 소식 글감 4주치 · AI 지시문 7종 |

- 진단이 끝나면 채우기 메뉴에 **주황 점**이 붙고, 결과 맨 아래에 **채우기 도구로 →** 버튼이 생깁니다.
- 진단하기 전에 채우기를 열면 *먼저 진단을 돌리라*고 안내합니다. 채우기 문장은 진단이 읽어온
  업체명·지역·키워드·시설·부족한 항목을 재료로 쓰기 때문에, 진단 없이 만들면 빈칸투성이가 됩니다.
- 마지막에 본 메뉴는 기억해 둡니다. 새로고침해도 그 자리에서 이어집니다.

```
index.html   진단 도구 본체 (단독 실행 가능)
server.js    로컬 서버 — 자동 수집 · 순위 추적 · AI 프록시 (선택)
```

## PC · 휴대폰 함께 쓰기

| | 휴대폰 (단독) | 휴대폰 (PC 켜짐 · 같은 와이파이) | PC |
|---|---|---|---|
| 진단 · 키워드 분석 · 문장 생성 | ✅ | ✅ | ✅ |
| 플레이스 자동 수집 | ❌ | ✅ | ✅ |
| 순위 조회 · 추적 | ❌ | ✅ | ✅ |
| 상위 3곳 경쟁 분석 | ❌ | ✅ | ✅ |

휴대폰 단독으로 안 되는 이유는 네이버가 브라우저의 직접 요청을 막기 때문입니다.
PC의 도우미를 거치면 폰에서도 전부 됩니다 — 설정 방법은 아래 B 항목에 있습니다.

**입력값은 기기마다 자동 저장**됩니다(localStorage). 새로고침해도, 며칠 뒤 다시 열어도 그대로입니다.

**기기를 옮길 때**는 페이지 하단 `다른 기기로 이어서 하기`에서:

1. 보내는 기기 — `코드 만들어 복사` → 카카오톡 '나에게 보내기'에 붙여넣기
2. 받는 기기 — 그 코드를 칸에 붙여넣고 `코드 불러오기`

업체명·지역·키워드·소개글·시설·체크 상태가 전부 그대로 넘어갑니다.
서버 없이 동작하므로 휴대폰↔PC, 집↔매장 어디서든 됩니다.

**다크 테마**는 기기 설정을 따라갑니다. 밤에 폰으로 봐도 눈이 편합니다.

## 휴대폰만으로 쓰기 — 터미널 없이 (권장)

집 PC를 켜 두는 게 번거로우면, 서버를 인터넷에 올려 두면 됩니다.
그러면 폰에서 주소만 열면 은코치처럼 바로 동작합니다.
**설치도 터미널도 필요 없고, 폰 브라우저에서 탭 몇 번이면 끝납니다.**

1. 폰에서 [render.com](https://render.com) → **Get Started** → **GitHub 로 로그인**
2. **New +** → **Blueprint** → 이 저장소(`development_place`) 선택 →
   브랜치를 `claude/webpage-dev-analysis-1rmgca` 로 지정 → **Apply**
   (저장소 안의 `render.yaml` 을 읽어 알아서 띄웁니다. 고를 것이 없습니다.)
3. 배포가 끝나면 `https://gym-place-check-xxxx.onrender.com` 같은 주소가 나옵니다
4. 대시보드 → **Environment** → `ACCESS_KEY` 값을 복사
5. 폰 브라우저에서 **`https://그-주소/#k=복사한값`** 을 열고 **북마크**
   → 키가 폰에 저장돼서 다음부터는 북마크만 누르면 됩니다

> **무료 요금제는 15분쯤 안 쓰면 서버가 잠듭니다.**
> 다시 열 때 첫 화면이 1분쯤 걸리고, 그동안 "서버를 깨우는 중입니다" 라고 나옵니다.
> 두 번째부터는 바로 뜹니다.

> **먼저 알아두실 것** — 네이버가 데이터센터에서 오는 요청을 막을 수 있습니다.
> 집 PC(가정용 인터넷)에서는 정상 응답(HTTP 200)이 확인됐지만, 클라우드에서도
> 같을지는 올려 봐야 압니다. 막히면 수집 결과가 비고, 화면이 그렇게 알려 줍니다.
> 그때는 아래 B(집 PC) 방식으로 돌아가면 됩니다. **올려 보는 데 드는 비용은 없습니다.**

`ANTHROPIC_API_KEY` 를 Environment 에 넣으면 AI 문장 생성도 폰에서 됩니다.
안 넣으면 그 기능만 꺼지고 나머지는 전부 동작합니다.

## 두 가지 실행 방법

### A. 수동 모드 — 설치 없음

`index.html`을 더블클릭해서 브라우저로 엽니다. 휴대폰에서도 그대로 씁니다.
진단·키워드 분석·문장 생성은 전부 됩니다.

### B. 서버 모드 — 자동 수집 + 순위 추적 + 경쟁 분석

**더블클릭으로 실행합니다. 명령어를 칠 필요 없습니다.**

| 운영체제 | 실행할 파일 |
|---|---|
| 윈도우 | `start.bat` |
| 맥 | `start.command` (처음 한 번은 우클릭 → 열기) |

Node.js 18 이상만 있으면 됩니다(`https://nodejs.org`에서 LTS 설치).
**npm install 불필요** — 외부 의존성이 하나도 없습니다.
브라우저가 알아서 열리고, 페이지 상단에 `자동 수집 · 순위 추적` 패널이 나타납니다.

터미널을 쓰신다면 `node server.js` 도 동일합니다.

#### 휴대폰에서도 쓰기

PC에서 서버를 켜면 화면과 터미널에 **휴대폰용 주소**가 나옵니다.

```
휴대폰에서      http://192.168.0.12:5173/#k=xxxxxxxx
```

같은 와이파이에 연결한 뒤 휴대폰 브라우저로 한 번 접속해 **북마크**해 두세요.
그 뒤로는 북마크만 누르면 폰에서도 자동 수집·순위 조회·경쟁 분석이 전부 됩니다.
(PC가 켜져 있고 같은 와이파이일 때)

주소 뒤의 `#k=...`는 **접근 키**입니다. 서버를 0.0.0.0으로 열면 같은 와이파이의
다른 기기도 접근할 수 있어서, 외부 기기 요청에만 키를 요구합니다.
키는 `data/access-key.txt`에 저장되므로 서버를 다시 켜도 북마크가 계속 동작합니다.
휴대폰 접속이 필요 없다면 `HOST=127.0.0.1 node server.js`로 이 PC만 열 수 있습니다.

#### PC 켤 때 자동 실행 (선택)

**윈도우** — `Win+R` → `shell:startup` → 열린 폴더에 `start.bat` 바로가기를 넣습니다.

**맥** — 시스템 설정 → 일반 → 로그인 항목 → `+` 로 `start.command` 추가.

#### 순위 자동 기록 (선택)

브라우저를 열지 않고 순위만 기록합니다. 스케줄러에 걸어두면 추이가 알아서 쌓입니다.

```bash
node server.js --track "강남역 헬스장" "https://map.naver.com/p/entry/place/1234567890"
```

- 맥/리눅스 — `crontab -e` 에 `0 9 * * * cd /경로 && node server.js --track "키워드" "URL"`
- 윈도우 — 작업 스케줄러에서 매일 실행 등록

기록은 `data/rank-history.json`에 쌓이고, 페이지의 순위 조회에서 ▲▼ 변동으로 보입니다.

| 기능 | 설명 |
|---|---|
| **정보 자동 수집** | **플레이스 주소 한 줄만 넣으면 1·2·3단계가 거의 다 채워집니다** |
| 순위 조회 | 목표 키워드로 검색했을 때 내 가게가 몇 위인지 조회합니다 |
| 순위 추적 | 조회할 때마다 `data/rank-history.json`에 기록되고, 직전 대비 ▲▼ 변동을 표시합니다 |
| **상위 3곳 분석** | **상위권이 왜 뜨는지 분석하고, 우리가 뭘 해야 하는지 뽑아냅니다** |
| AI 프록시 | API 키가 서버에만 있고 브라우저로 내려오지 않습니다 |

### 상위 3곳 분석 — 이 도구의 핵심

목표 키워드로 검색해 **상위 3곳을 실제로 수집·비교**합니다.

**1. 지표 비교 + 3위 진입선**

| 지표 | 우리 | 1위 | 2위 | 3위 | 3위 진입선 |
|---|---:|---:|---:|---:|---|
| 방문자 리뷰 | 41개 | 312 | 268 | 190 | **149개 부족** |
| 사진 | 12장 | 88 | 64 | 52 | **40장 부족** |

상위 3곳 중 **가장 낮은 값**이 곧 3위 진입선입니다. 막연한 "많이 채우세요"가 아니라 숫자로 나옵니다.

**2. 상위권이 공통으로 쓰는데 우리에겐 없는 표현**

헬스장 도메인 어휘 사전(시설·프로그램·운영조건·대상·기구·신뢰 6개 범주)으로
상위권 소개글을 훑어, **2곳 이상이 쓰는데 우리에겐 없는 표현**을 뽑습니다.

> 누락: 무료주차(3/3곳), 샤워실(3/3곳), 24시간(3/3곳), 무료체험(3/3곳), PT, 락커, 운동복 …

`무료주차`가 잡히면 `주차`는 자동으로 흡수해 목록이 부풀지 않습니다.

**3. 거리 추정**

네이버의 실제 검색 좌표는 알 수 없지만, **상위권이 몰려 있는 지점이 그 키워드의 중심**입니다.
상위 3곳 좌표의 중심을 검색 중심으로 잡고 우리 거리를 잽니다.

**4. 결론 — 반드시 3개로 나눕니다**

여기가 이 기능의 핵심입니다. 격차를 뭉뚱그리면 실행할 수 없는 목록이 됩니다.

| 분류 | 내용 |
|---|---|
| 🟢 오늘 할 수 있는 것 | 소개글 길이, 누락 표현 추가, 사진 업로드 |
| 🟡 시간이 걸리는 것 | 리뷰·저장·평점 — 몇 주~몇 달. 구매는 제재 대상 |
| ⚪ 바꿀 수 없는 것 | 거리. 이 경우 **다른 키워드로 목표를 바꾸라고** 조언합니다 |

AI를 쓰려면 키를 환경변수로 넣고 서버를 켜세요:

```bash
ANTHROPIC_API_KEY=sk-ant-... node server.js
```

## 이 점수의 근거 — 어디까지가 사실인가

네이버는 순위 계산식을 공개하지 않는다. 그래서 근거의 세기를 나눠 둔다.

| 구분 | 내용 | 근거 |
|---|---|---|
| 3축 구조 | 적합도 · 인기도 · 거리 | 네이버가 밝힌 취지 (연관도·이용자 반응·거리) |
| 45 / 40 / 15 | 축별 배점 | **추정.** 네이버는 비중을 공개한 적이 없다 |
| 항목 존재 여부 | 카테고리·영업시간·편의시설·가격·대표키워드·소개글·사진·예약 | 스마트플레이스 가이드가 채우라고 안내하는 것들 |
| 항목별 숫자 기준 | 사진 30장, 리뷰 50개, 답글 90% 등 | **추정.** 방향은 업계에서 반복 관찰되나 숫자는 임의 |
| 키워드 매칭 8점 | 목표 키워드 × 소개글 실제 대조 | **계산.** 가정이 없다 |

### 추정을 실측으로 바꾸는 장치 — 기준 보정

`상위 3곳 분석`을 돌리면, 그 키워드에서 실제로 3위 안에 든 가게들의 숫자가 나온다.
그 최저값(진입선)으로 추정 기준을 갈아치운다.

```
보정 전: 사진 30장 이상        ← 내가 정한 숫자
보정 후: 사진 52장 이상        ← "강남역 헬스장" 상위 3곳 중 최저값
```

지역·업종·경쟁 강도가 다 다르므로 전국 공통 숫자보다 그 키워드의 실제 진입선이 맞다.
보정된 항목에는 `기준 52장` 배지가 붙고, 눌러 보면 상위 3곳의 실제 값이 나온다.
보정 전에는 화면에 "이 숫자는 추정값"이라고 밝힌다.

### 그래도 남는 한계

점수가 오르는 것과 순위가 오르는 것은 다르다. 이 점수는 **채울 수 있는 것을 채웠는가**의
진척도이고, 네이버가 매길 점수가 아니다. 실제 인과는 `순위 기록`과 `개선 기록`으로
사장님 가게에서 확인하는 수밖에 없다.

### 주소 한 줄 → 나머지 자동

서버가 켜져 있으면 `정보 자동 수집` 버튼 하나로 이만큼이 채워집니다.

| 단계 | 자동으로 채워지는 것 | 근거 |
|---|---|---|
| 1단계 | 업체명 | 수집값 |
| | **지역** | 등록된 대표키워드의 역명 → 없으면 주소(동 > 구 > 시) |
| | **주력 업종** | 카테고리 문자열 판별 |
| | **1개월 가격** | 메뉴 중 "1개월/한달" 항목 |
| 2단계 | 소개글 | 수집값 |
| | **대표키워드** | 등록된 키워드 목록 |
| | **목표 키워드** | 등록된 대표키워드를 그대로 (없으면 지역·업종으로 추측) |
| 3단계 | 체크 12개 | 아래 자동 판정 표 참조 |

**목표 키워드는 등록된 대표키워드를 최우선으로 씁니다.**
주소는 "어디에 있는가"일 뿐이고, 대표키워드는 "어디로 검색되고 싶은가"입니다.
주소가 역삼동이어도 대표키워드가 `강남역헬스장`이면 목표는 강남역입니다.

**이미 손으로 입력한 값은 덮어쓰지 않습니다.** 빈 칸만 채웁니다.
무엇을 어떤 근거로 채웠는지 화면에 남으므로, 틀렸으면 그 자리에서 고치면 됩니다.

### 22개 중 16개가 자동, 6개만 손으로

| 판정 방식 | 개수 | 항목 |
|---|---:|---|
| **입력값으로 계산** | 4 | 키워드 매칭, 소개글 길이, 대표키워드 수, 업체명 스터핑 |
| **수집값으로 판정** (서버 실행 시) | 12 | 사진 수, 리뷰 수, 블로그 리뷰, 저장 수, 예약·톡톡, 홈페이지, 영업시간, 가격, 편의시설, 사업자 인증, 카테고리, 소식 |
| **직접 확인** | 6 | 대표사진 내용, 구역별 사진, 사진 최신성, 리뷰 답글률, 최근 리뷰, 지도 핀 |

자동 판정된 항목은 체크박스가 알아서 켜지고 `자동` 배지가 붙습니다.
배지에 마우스를 올리면 **무슨 근거로 판정했는지**(예: "사진 46장") 나옵니다. 직접 고쳐도 됩니다.

**근거가 없으면 판정하지 않습니다.** 수집에 실패했거나 사진을 봐야 아는 항목은
추측으로 채우지 않고 "직접 확인"으로 남깁니다. 추측으로 채우면 점수가 거짓이 되기 때문입니다.

남은 6개가 자동화되지 않는 이유:

- 대표사진이 시설 전경인지, 어느 구역 사진인지 → 사진을 봐야 압니다
- 사진 업로드 시점 → 공개 정보에 없습니다
- 리뷰별 답글 유무, 리뷰 작성일 → 리뷰를 하나씩 열어야 합니다
- 지도 핀이 실제 출입구인지 → 물리적으로 확인해야 합니다

### 적합도는 체크가 아니라 계산입니다

목표 키워드와 소개글을 넣으면:

- 키워드가 소개글·업체명·대표키워드에 실제로 있는지 **토큰 단위로 매칭**
- 구문 전체 매칭 / 부분 매칭 / 약한 매칭 / 매칭 없음 판정
- 단어별 출현 횟수와 위치 표시
- **과다 반복 감지** — 12회 이상이거나 밀도 6% 초과(300자 이상일 때)면 어뷰징 경고
- **업체명 키워드 스터핑 감지** — 지역·업종어가 2개 이상 박혀 있으면 경고

### 개선 기록 — 내 가게의 실전 데이터를 쌓습니다

이 도구의 약점은 **실전 컨설팅 사례가 없다**는 것입니다.
항목과 배점은 공개된 노출 원리에서 나온 추정이지, 수백 건의 검증을 거친 값이 아닙니다.

남의 사례를 흉내 낼 수는 없으니, **내 가게 데이터를 직접 쌓는 장치**를 넣었습니다.

1. 할 일을 처리하면 `완료`를 눌러 기록
2. 순위를 조회하면 그 기록과 시간순으로 겹쳐 표시

```
7/29  이용권·PT 가격을 공개했다 완료
7/29  "강남역 헬스장" 12위
8/02  사진이 30장 이상 등록되어 있다 완료
8/05  "강남역 헬스장" 8위  ▲ 4
```

**인과로 단정하지 않습니다.** 경쟁사 변화·계절 같은 다른 요인도 순위를 움직입니다.
다만 같은 작업이 여러 번 순위 상승 앞에 나온다면 그건 신호로 볼 만합니다.

기록은 브라우저에 저장되고(서버 없이 휴대폰에서도 기록됩니다),
기기 간 이어쓰기 코드에 함께 담겨 옮겨집니다.

### 병목 축 진단

세 축 중 가장 낮은 축을 지목하고, 왜 그 축이 발목을 잡는지 인과 사슬로 보여줍니다.

## 네이버 응답이 깨졌을 때

네이버는 공개 API가 없고 내부 응답 구조를 예고 없이 바꿉니다.
그래서 이 서버는 **경로를 고정해 파싱하지 않고**, 여러 엔드포인트를 순서대로 시도한 뒤
응답 트리 전체를 훑어 **필드 이름으로 값을 주워담습니다.** 구조가 바뀌어도 잘 버팁니다.

그래도 깨지면 점검 명령으로 원인을 확인하세요:

```bash
node server.js --probe "강남역 헬스장" "https://map.naver.com/p/entry/place/1234567890"
```

출력은 `[0] 플레이스 ID 확인` → `[1] 플레이스 정보 수집` → `[2] 순위 조회` 순서입니다.
`[0]`에서 멈추면 주소 문제, `[1]`·`[2]`에서 멈추면 네이버 응답 문제입니다.

`[1]`이나 `[2]`가 실패했다면, 응답 안에 무엇이 들어있는지 지문을 뜹니다:

```bash
node server.js --dump "강남역 헬스장" "https://map.naver.com/p/entry/place/1234567890"
```

엔드포인트마다 HTTP 상태·본문 길이·`window.__변수__` 이름·`<script id>`·
차단 문구 여부·**필드 이름이 본문에 원문으로 있는지**를 출력합니다.
마지막 항목이 판단의 핵심입니다 — 필드 이름이 보이면 컨테이너만 못 찾는 것이고,
안 보이면 그 응답에는 데이터가 애초에 없습니다(별도 API 호출로 그려지는 페이지).

본문 전문은 `data/dump/` 에 저장됩니다(`.gitignore` 처리됨).

> 키워드와 URL 사이에 **공백을 반드시** 두세요. `"키워드""URL"` 처럼 붙여 쓰면
> PowerShell이 둘을 한 인자로 합칩니다. (붙여 써도 알아서 갈라내지만 경고가 뜹니다.)
>
> `naver.me` 단축 링크도 됩니다. 리다이렉트를 따라가 실제 번호를 찾습니다.
> 단축 링크가 열리지 않으면 지도 주소창의 긴 주소를 쓰세요.

API 엔드포인트:

| 경로 | 설명 |
|---|---|
| `/api/place?url=` | 플레이스 정보 수집 |
| `/api/rank?keyword=&url=` | 순위 조회 (자동 기록) |
| `/api/competitors?keyword=&url=&top=3` | 상위 N곳 경쟁 분석 |
| `/api/history?keyword=` | 순위 기록 조회 |
| `/api/ai` | Claude 프록시 (POST) |

어떤 엔드포인트를 시도했고 각각 어떻게 실패했는지 전부 출력됩니다.
그 출력을 그대로 알려주시면 파서를 맞출 수 있습니다.

> **참고** — 개발 환경의 네트워크 정책상 네이버 접속이 차단되어 있어,
> 수집·순위 로직은 응답을 흉내 낸 테스트로만 검증했습니다.
> 실제 네이버 응답에 대한 첫 검증은 사장님 PC에서 위 `--probe`로 하셔야 합니다.

## 이 도구가 하는 일과 못 하는 일

**하는 일** — 통제 가능한 항목의 누락을 찾아냅니다.
매일 보느라 안 보이던 빈칸을 남의 눈으로 훑어주는 것, 그리고 목표 키워드가
실제로 매칭되는지 계산해주는 것이 핵심 가치입니다.

**못 하는 일** — 네이버 점수를 알려주지 못합니다.
네이버는 순위 알고리즘을 공개하지 않습니다. 여기 나오는 점수는 네이버 점수가 아니라
**공개된 노출 원리를 바탕으로 만든 체크리스트의 점수**입니다.
적합도는 입력값으로 실제 계산하지만, 인기도·거리는 자가 체크 기반입니다.

정보를 채운다고 순위가 오르는 게 아닙니다.
**채워야 노출될 자격이 생기고 → 노출돼야 클릭이 생기고 → 클릭이 쌓여야 순위가 오릅니다.**
이 도구는 그 출발선에 서게 해주는 역할입니다.

리뷰·저장수 구매 같은 어뷰징은 네이버가 갈수록 정교하게 잡아냅니다. 권하지 않습니다.
