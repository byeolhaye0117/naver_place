# 헬스장 플레이스 진단 도구

헬스장·피트니스 센터 전용 네이버 플레이스 진단 도구입니다.
**네이버가 순위를 매기는 3개 축(적합도 · 인기도 · 거리)** 구조로 진단하고,
목표 키워드가 실제로 매칭되는지 계산하며, 원하면 **현재 순위까지 추적**합니다.

개인 운영용입니다. 외부 공개나 상담 유도 기능은 없습니다.

## 화면 구조

매일 같은 자리를 눌러 쓰는 도구라, 소개 문구 없이 **들어오면 바로 숫자**가 나옵니다.

```
┌────────────────────────────────────────────────────────────┐
│ 💪 플레이스 진단   진단  채우기 도구●   저장내역 입력값 이어쓰기 │  ← 흰 바 + 텍스트 메뉴
├────────────────────────────────────────────────────────────┤
│ 🔍 플레이스 주소 또는 ID 붙여넣기                    [수집]   │  ← 주소 넣는 줄
├────────────────────────────────────────────────────────────┤
│ 스트롱짐 피트니스                      [순위 조회][상위 3곳]  │
│ 강남역 헬스장 10위                                          │
│ ┌────┐┌────┐┌────┐┌────┐                                  │
│ │순위││리뷰││사진││소개│   ← 큰 숫자 4개                     │
│ │10위││41개││12장││56자│                                    │
│ └────┘└────┘└────┘└────┘                                  │
│ ┃ 진단 점수            ┃ 할 일 19건                         │  ← 주황 세로 막대 제목
│ │ 24 / 100            │ ① 소개글  ② 대표키워드  ③ 편의시설   │
└────────────────────────────────────────────────────────────┘
```

**색과 글자는 은코치 화면을 기준으로 잡았습니다.**

| | 값 |
|---|---|
| 바탕 | `#F4F6F8` 따뜻한 회색 |
| 글자 | `#1B1E23` / 보조 `#626D7A` |
| 포인트 | `#C2410C` 진한 벽돌 주황 |
| 선 | `#E8EAED` · 모서리 `14px` |
| 폰트 | Pretendard (없으면 시스템 한글 폰트) |

- **섹션 제목은 주황 세로 막대**로 구분합니다. 은코치 화면의 가장 눈에 띄는 요소입니다.
- **외부 폰트를 불러오지 않습니다.** 인터넷이 끊겨도, `index.html`을 그냥 열어도
  화면이 그대로여야 하기 때문입니다. 기기에 Pretendard가 깔려 있으면 그것을 씁니다.
- **860px 아래**(휴대폰)에서는 설정 링크만 서랍(☰)으로 접히고, **진단/채우기 전환은
  한 줄로 내려와 그대로 보입니다.** 폰으로 쓰는 화면이라 두 번 눌러 바꾸게 하지 않습니다.
- 채우기 페이지는 **도구 목록만** 먼저 보여줍니다. 일곱 개를 한꺼번에 펼쳐 두면
  무엇을 봐야 할지 모르게 되기 때문입니다. **하나를 고르면 그것만** 나오고,
  `← 도구 목록`으로 돌아갑니다. 마지막에 보던 도구는 기억해 둡니다.
- **한 번 수집한 가게는 다시 들어올 때 진단이 자동으로 돌아갑니다.**
- **다른 가게 주소를 넣으면** 이전 가게 내용을 저장 내역에 넣어 두고 화면을 비운 뒤
  새로 채웁니다. 같은 가게를 다시 수집할 때는 손으로 고친 값을 그대로 둡니다.
- 어두운 화면 설정(다크 모드)을 쓰면 그에 맞춰 바뀝니다.

### 도구마다 "이렇게 하면 좋아요"가 함께 나옵니다

만들어만 주고 **언제 쓰는지, 어디에 넣는지**를 안 알려주면 결국 안 쓰게 됩니다.
도구를 고르면 그 도구의 사용법이 위에 먼저 나옵니다.

```
💡 이렇게 하면 좋아요
쿠폰, 소식 제목, 톡톡 단체 메시지, 광고 문구를 넣어야 할 때. 칸마다 글자수 제한이 다릅니다.

 ① 채울 칸을 찾으세요. 칸 이름 옆에 제한 글자수와 넣는 자리가 적혀 있습니다.
 ② 문구 옆 글자수를 보고 하나 고른 뒤 복사를 누르세요. 한 줄씩 따로 복사됩니다.
 ③ 적힌 자리에 그대로 붙여넣으세요. 전부 제한 안에 들어가므로 저장이 막히지 않습니다.
 ④ 플레이스광고 5칸은 다섯 개를 다 다르게 넣으세요.

이것만은 - 쿠폰과 체험은 사장님이 새로 거실 혜택이라 제안으로 드립니다.
          실제로 하실 것만 고르세요. 안 지킬 혜택을 걸면 그 자리에서 신뢰를 잃습니다.
```

- **언제 쓰나** 한 줄 → **순서 3~4단계** → **이것만은** 한 줄. 세 부분으로 고정입니다.
- 순서에는 **네이버의 어느 메뉴에 넣는지**를 그대로 적습니다
  (`스마트플레이스 - 업체정보 - 상세설명`처럼).
- **이것만은**에는 그 도구에서 제일 크게 손해 볼 수 있는 것 하나만 적습니다.
  없는 시설 적기, 안 지킬 쿠폰 걸기, AI가 지어낸 문장 그대로 올리기 같은 것들입니다.

### 소개글 — 8단 구성

소개글까지 내려온 손님은 **이미 마음이 기운 사람**입니다. 마지막 불안 한두 개가
안 지워지면 뒤로가기를 누릅니다. 그래서 자랑이 아니라 **불안을 지우는 순서**로 씁니다.

| 단계 | 답하는 질문 | 재료 | 출처 |
|---|---|---|---|
| 0 훅 | 여기가 내 얘기인가 | 손님 유형별 첫 줄 | 시설 보고 자동 선택 |
| 1 문제 공감 | 지금 어떤 상황인가 | 목표 키워드 | 입력 |
| 2 심각성 | 미루면 어떻게 되나 | — | — |
| 3 해결책 | 어떻게 해결하나 | 망설임 5가지 | 체크된 시설만 |
| — | 처음 오면 뭘 하나 | 업종, 인바디, GX | 자동 |
| 4 증명 | 진짜인가 | **실제 리뷰 문장 인용** | **네이버 자동 수집** |
| 5 방문 유도 | 지금 갈 이유 | **메뉴에 걸어둔 이벤트** | **네이버 자동 수집** |
| 6 찾아오는 길 | 어떻게 가나 | **지하철역·출구·도보분, 버스정류장** | **네이버 자동 수집** |
| 7 영업정보 | — | **결제수단, 편의시설** | **네이버 자동 수집** |

**굵게 표시한 네 단계가 이 도구의 핵심입니다.** 보통은 사장님이 손으로 적어 넣는
항목인데, 네이버 응답 안에 이미 들어 있습니다. 주소 한 줄만 넣으면 이렇게 나옵니다.

```
지하철   봉명역 2번 출구 · 도보 11분 (616m)
버스     쌍용패션거리 도보 2분 · 열린치과 도보 3분 · 천안여상입구 도보 5분
리뷰     "혼자 조용히 집중하기 좋은 분위기라 마음에 듭니다" 외 2건
이벤트   7월은 무료이용
결제     제로페이, 간편결제
```

**순위와 이어지는 지점은 세 곳입니다.**

1. **3·6단계에 거점키워드가 박힙니다** — 검색어와 문서가 맞아야 후보에 듭니다
2. **6단계의 역·정류장·상권 이름은 저경쟁 검색어입니다** — "쌍용패션거리"처럼
   그 동네 사람만 쓰는 말은 경쟁자가 거의 없어 먼저 자리를 잡기 좋습니다
3. **5단계의 예약·문의 유도는 클릭으로 이어집니다** — 클릭·저장은 인기도 신호입니다

**차별점 한 줄**

시설은 옆집에도 있습니다. `"왜 하필 여기냐"`에 답하는 한 줄이 있어야 안내문이 아니라
설득이 됩니다. 1단계에 칸을 두고, **빈칸 앞에서 막히지 않게 근거 있는 후보를 제안**합니다.

- 손님이 리뷰에서 자주 쓴 말에서 (가격·혼자 조용히·처음 시작…)
- 남들이 잘 안 갖춘 시설에서 (24시간·여성전용·무인출입…)
- 사장님이 `찾아오는 길`에 직접 적어 둔 첫 줄에서 (대개 이게 제일 정확합니다)

**업종별로 말이 바뀝니다.** 필라테스에 "기구 눈치"는 안 맞고 크로스핏에는 더 안 맞습니다.
헬스장·PT·필라테스·크로스핏 각각 손님이 쓰는 말로 갈아 끼웁니다.

**다른 표현으로 다시 만들 수 있습니다.** 뜻이 같은 다른 문장 세 벌을 돌립니다.
사실은 바뀌지 않고 말투만 바뀝니다.

**지키는 규칙**

- **체크 안 한 시설은 한 글자도 쓰지 않습니다.** 없는 시설을 적으면 방문 첫날
  들통나고 그게 리뷰로 남습니다. 3단계의 각 칸은 해당 시설이 켜져 있을 때만 나옵니다.
- 시설은 네이버 편의시설 목록뿐 아니라 **사장님이 직접 쓴 소개글·찾아오는 길·메뉴판**에서도
  읽어 켭니다. 사장님이 쓴 글이라 지어낼 위험이 없습니다.
- 분량 1,200~1,800자. 넘치면 **인용 리뷰를 줄여서**, 모자라면 **사실인 문단을 하나 더 붙여서**
  범위 안으로 맞춥니다. 시설 0개·리뷰 없는 가게도 1,312자가 나옵니다(분량용 빈말은 안 넣습니다).
- `최고의`, `프리미엄` 같은 추상적 수식어로 시작하지 않습니다.

### 붙여넣기 전 자동 점검 — 위험 경고가 아닙니다

책이나 강의에서 종이에 체크하라고 주는 목록을 **화면이 글을 읽고 판정합니다.**

```
붙여넣기 전 점검                                    8 / 9
 ✅ 첫 줄이 손님의 고민으로 시작한다   퇴근하면 이미 문 닫혀 있지 않나요
 ✅ 5단계가 다 들어갔다               공감 · 심각성 · 해결책 · 증명 · 유도
 ⚠️ 거점키워드가 본문에 들어갔다       쌍용동 헬스장 3회 · 쌍용동 PT 1회 · ○○ 0회
 ✅ 실제 리뷰를 인용했다              수집한 리뷰 3개 중 인용
 ✅ 찾아오는 길에 랜드마크가 있다      봉명역, 쌍용패션거리, 열린치과
 ✅ 방문 유도가 있다                  메뉴의 이벤트를 인용
 ✅ 글자수 1,200~1,800자             1,739자
 ✅ 네이버 금지문자 0개               이모지 · 화살표 · 가운뎃점 등 없음
 ✅ 추상적 수식어로 시작하지 않는다     '최고의' '프리미엄' 없음
```

⚠️ 항목은 **무엇이 부족한지까지** 적습니다. 위 예시는 3순위 키워드가 본문에
0회라서, 그 키워드를 넣을지 뺄지는 사장님이 정하시면 됩니다.

**못 채운 줄을 ⚠️ 로 그리고 빨갛게 칠했더니 "제재당하는 건가" 하고 놀라시는 분이 있었습니다.**
여기는 위험 목록이 아니라 **아직 안 채운 칸의 목록**입니다. 하나도 안 채워도 제재는 없고
글이 조금 덜 좋을 뿐입니다. 그래서 표시와 문구를 바꿨습니다.

- 머리말은 `9 / 11 채움` — 몇 개를 **채웠는지**로 읽힙니다
- 못 채운 줄은 `○` 로 표시하고 제목을 빨갛게 칠하지 않습니다
- 표 맨 위에 한 줄 — *"아직 안 채운 칸이 2개 있습니다. **제재와는 상관없습니다.**"*

**진짜 위험한 것은 아래 주의 상자에 따로 있습니다** — 업체명에 키워드 욱여넣기,
리뷰·저장수 구매, 그리고 **실제로 없는 시설 적기**. 이 셋만 피하면 됩니다.

**못 채운 줄은 그 자리에서 고칩니다.** 진단 화면으로 돌아가 칸을 찾아 채우고 다시
오라고 하면, 그 왕복 때문에 결국 안 채우게 됩니다. 차별점이 비어 있으면 점검표 안에
**후보 버튼**이 바로 나오고, 누르면 넣고 글까지 다시 만듭니다.

### 목표 키워드는 하나도 빠뜨리지 않습니다

목표 키워드를 세 개 받아 놓고 글에는 두 개만 넣고 있었습니다. 3순위가 **0회**로 남아
점검표에서 **우리 스스로 미달**을 냈습니다. 사장님더러 직접 넣으라고 할 일이 아니라,
받았으면 다 써야 합니다.

빠진 키워드는 **맨 끝 한 줄**로 모읍니다. 본문 중간에 억지로 끼워 넣는 것보다 읽는 데
방해가 덜 하고, 실제 플레이스 소개글들도 끝에 키워드 줄을 둡니다.
**이미 본문에 나온 키워드는 다시 적지 않습니다** — 그게 반복이고 어뷰징으로 보입니다.

```
쌍용동헬스장 3회 · 쌍용동pt 1회 · 쌍용동24시헬스장 1회   ← 예전엔 3순위가 0회

... (맨 끝 줄)
쌍용동24시헬스장을 찾고 계셨다면 편하게 들러 보세요.
궁금한 점은 전화나 톡톡으로 먼저 물어보셔도 됩니다.
```

### 수집한 재료는 새로고침해도 남습니다

리뷰 본문·지하철역·버스정류장·진행 이벤트를 **화면을 닫으면 잃고 있었습니다.**
그러면 소개글에서 리뷰 인용과 찾아오는 길이 통째로 빠지고, 점검표에도
*"리뷰 본문 수집 안 됨 / 역·정류장 정보 없음"* 으로 남았습니다.
**폰에서 열면 PC 에서 만든 것보다 나쁜 글이 나왔다**는 뜻입니다.

이제 재료도 함께 저장합니다. 리뷰는 10개, 블로그는 5개까지만 담아 저장 공간을
낭비하지 않습니다 (실측 1.8KB). 기기 사이 이어쓰기에도 같이 따라갑니다.

### 키워드 발굴 — 검색량 대신 "내 실제 순위"로

순위는 계단입니다. 경쟁 심한 키워드에 바로 달려들면 점수 쌓일 발판이 없어
몇 달이 지나도 제자리입니다. **이미 30위 안에 들어 있는 키워드**를 1페이지로
올리는 편이 빠르고, 그렇게 쌓인 점수는 더 어려운 키워드에도 붙습니다.

문제는 "어떤 키워드가 만만한가"를 아는 방법입니다. 보통은 네이버 검색광고 API로
월 검색량과 경쟁도를 봅니다. **우리는 API 없이, 후보를 만들어 각각 실제로 순위를
조회합니다.** 검색량보다 직접적인 근거입니다 — 지금 몇 위인지가 곧 답이니까요.

```
키워드              내 순위   판정
쌍용동헬스장           3위    1페이지    이미 잡았습니다. 유지만 하세요
봉명역헬스장           8위    2페이지    거의 다 왔습니다. 여기부터 미세요
쌍용동헬스장추천       14위    한 발 남음  제일 먼저 공략할 자리입니다
쌍용동헬스            22위    한 발 남음
쌍용동피트니스         45위    45위       뒤로 미루고 위쪽부터 잡으세요
```

- **후보는 자동으로 만듭니다** — 지역 + 업종 + 수식어 조합에, 네이버에서 가져온
  **역·상권 이름**을 더합니다(`봉명역헬스장`, `쌍용패션거리헬스장`). 그 동네 사람만
  쓰는 말이라 경쟁이 적습니다. 정류장 이름이라도 `열린치과`처럼 아무도 검색하지 않는
  것은 걸러냅니다.
- 마음에 안 드는 후보는 눌러서 뺄 수 있습니다. 한 번에 8~12개까지 조회합니다.
- **먼저 공략할 키워드를 목표 키워드 칸에 바로 넣는** 버튼이 있습니다. 넣으면
  진단과 소개글이 그 키워드 기준으로 다시 계산됩니다.

### 사진 수 — 무엇을 센 값인지 갈라서 보여줍니다

네이버는 사진 수를 한 가지로 주지 않습니다. 한동안 **사진 탭에서 가장 큰 목록을
사진으로 세고** 있었는데, 실측해 보니 그 목록이 **메뉴 19개**였습니다. 사진이 아니라
메뉴가 19개였습니다. 그래서 위 큰 숫자(15장)와 아래 확인 상자(19장)가 어긋났습니다.

이제 네이버가 주는 값을 갈라서 봅니다.

| 값 | 뜻 | 점수에 쓰나 |
|---|---|---|
| `images.totalImages` **15** | 사장님이 직접 올린 사진 | ✅ **이것만 씁니다** |
| `topPhotos.total` 31 | 맨 위 큰 사진 자리에 도는 전체 (업체 사진 + 동영상 + 손님 사진) | 참고 |
| `photoTabInfo.clipTotal` 2 | 동영상 개수 | 참고 |
| `visitorReviewMediasTotal` 10,651 | 손님이 리뷰에 올린 사진·영상 | 참고 |
| `imageCount` 1 | 대표사진 한 장으로 보입니다 | ✕ |

**손님 사진을 섞어 세지 않습니다.** 만 장이 넘는 리뷰 사진을 합치면 "사진 충분함"으로
보이지만, 그건 사장님이 늘릴 수 있는 값이 아닙니다. 정작 채워야 할 **업체 사진** 자리를
놓치게 됩니다. 30장 기준도 업체 사진에만 적용합니다.

### 키워드 발굴 — 줄마다 "그래서 뭘 하면 되나"를 답합니다

순위만 늘어놓으면 그 표를 보고 할 일을 정할 수 없습니다. 특히 **"아직 밖"이 왜 밖인지**가
갈립니다. 우리가 그 말을 안 쓴 것과, 그 말은 쓰는데 다른 가게가 더 센 것은 완전히 다른
문제입니다. **앞엣것은 오늘 고칠 수 있고 뒤엣것은 아닙니다.**

그래서 그 검색어를 가르는 말(지역·업종어를 뺀 나머지)이 우리 소개글·업체명·대표키워드에
실제로 있는지 찾아보고 나눕니다.

| 구간 | 무엇을 하면 되나 |
|---|---|
| 1~10위 | 이미 잡았습니다. 대표키워드 5칸에 없으면 한 칸 넣으세요 |
| 11~30위 | **제일 싼 목표.** 소개글에 그 표현을 통째로 한 번 넣고 2주 뒤 다시 재세요 |
| 밖 · 그 말이 우리 글에 없음 | 실제로 하시는 거면 소개글에 한 번 쓰세요. 안 하시면 버리세요 |
| 밖 · 그 말은 있음 | 다른 곳이 더 센 것이라 지금 붙어도 오래 걸립니다 |

표 위에는 **이 순위가 무엇인지**를 먼저 적습니다 — 광고 자리가 아니라 그 말을 그대로
검색했을 때 나오는 실제 검색 결과 순서이고, 50곳까지 훑어서 없으면 "아직 밖"입니다.

**1페이지와 밖만 있고 중간(11~30위)이 비어 있으면** 그것도 따로 짚습니다. 그 동네 말은
이미 다 잡으셨다는 뜻이라, 옆 동네와 시 이름을 지역 칸에 더 넣고 후보를 다시 만들 때입니다.

### 대표키워드도 자동으로 가져옵니다

네이버는 대표키워드를 **`keywordList`** 라는 이름으로 응답에 실어 보냅니다.
`keywords` 만 찾다가 "관리자 전용 값이라 자동 수집이 불가능하다"고 **잘못 안내**하고
있었습니다. 이름만 맞추니 5칸이 그대로 딸려 옵니다.

**지역명이 안 들어간 키워드는 짚어 드립니다.**

```
대표키워드  씽용동헬스장, 쌍용동pt, 쌍용동24시헬스장, 천안쌍용동헬스장, 봉명동헬스장
           ⚠ 지역명(쌍용동)이 없는 키워드 2개 - 씽용동헬스장, 봉명동헬스장
             오타는 아닌지 확인해 주세요. 오타면 그 칸은 아무것도 못 잡습니다.
```

관리자 화면에서는 자기가 쓴 글이라 오타가 눈에 잘 안 띕니다. 실제로 `쌍용동`이
`씽용동`으로 등록돼 있어 5칸 중 하나가 아무것도 잡지 못하고 있었습니다.
(옆 동네 키워드처럼 일부러 넣은 것도 같이 잡히니, 판단은 사장님이 하시면 됩니다.)

**추천 5칸에는 왜 그 키워드인지도 같이 적습니다.** 번호만 다섯 줄 주면 넣을지 말지
판단할 근거가 없기 때문입니다. 지금 등록된 값과 비교해 **바꿀 칸**까지 짚어 드립니다.

```
1. 쌍용동헬스장  (7자, 이미 등록됨)
   - 목표 키워드 - 반드시 한 칸 차지해야 합니다
2. 쌍용동24시간헬스장  (11자, 새로 넣을 것)
   - 24시간 운영을 체크하셨습니다. 시간대로 찾는 손님이 따로 있습니다

[바꿔 볼 칸] 씽용동헬스장
  위 추천에 없는 값입니다. 2주간 유입이 없었다면 교체 후보입니다.
```

### 짧은 문구 모음 — 칸마다 다른 글자수를 세어 드립니다

네이버는 칸마다 글자수 제한이 다릅니다. 쿠폰명은 15자, 톡톡 제목은 20자,
플레이스광고 소재는 16자입니다. **넘기면 저장이 막히거나 뒤가 잘려서 말이 이상해집니다.**
소개글은 잘 써 놓고 이 칸들은 그냥 비워 두는 경우가 많습니다.

| 칸 | 제한 | 만드는 개수 | 넣는 자리 |
|---|---|---|---|
| 쿠폰 문구 | 15자 | 4개 | 스마트플레이스 > 쿠폰 > 쿠폰명 |
| 소식 제목 | 40자 | 4개 | 스마트플레이스 > 소식 > 제목 |
| 톡톡 메시지 제목 | 20자 | 3개 | 네이버 톡톡 > 단체 메시지 |
| 톡톡 메시지 본문 | 8줄 | 1벌 | 네이버 톡톡 > 단체 메시지 |
| 플레이스광고 소재 | 16자 | 5개 | 검색광고 > 플레이스광고 > 소재 |
| 파워링크 제목 | 15자 | 3개 | 검색광고 > 파워링크 > 제목 |
| 파워링크 설명 | 45자 | 3개 | 검색광고 > 파워링크 > 설명 |

```
쿠폰 문구   15자 이내              스마트플레이스 > 쿠폰 > 쿠폰명
  첫 방문 무료 체험                          10자   [복사]
  인바디 무료 측정권                         10자   [복사]
  1개월 등록 시 2주 연장                     14자   [복사]

플레이스광고 소재  16자 이내      검색광고 > 플레이스광고 > 소재
  쌍용동 헬스장 주차 가능                    13자   [복사]
  후기 4,668개 평점 5.0                     16자   [복사]
  1개월 89,000원                            11자   [복사]
```

- **글자수를 세어서 판정합니다.** 제한을 넘으면 주황으로 표시합니다. 위 화면처럼
  전부 들어가면 제목 옆에 `전부 제한 안`이 뜹니다.
- **길다고 자르지 않습니다.** 잘린 문구는 없느니만 못하기 때문에, 안 들어가는 부분은
  아예 빼고 만듭니다. 그래서 업체명이 길든 지역명이 길든 항상 제한 안에 들어갑니다.
- **수집한 값만 씁니다.** 체크한 시설, 수집한 가격, 실측 리뷰 수, 지하철역만 들어갑니다.
  다만 **쿠폰과 체험은 사장님이 새로 거실 혜택**이라 제안으로 드립니다. 실제로 하실 것만 고르세요.
- **플레이스광고 5칸은 서로 다른 이유**(위치·시설·후기·가격·체험)로 채웁니다.
  같은 말을 다섯 번 넣으면 나중에 어떤 문구가 눌렸는지 비교할 거리가 없습니다.
- **`역대급`, `최저가`, `1위` 같은 표현은 쓰지 않습니다.** 표시광고법 문제가 됩니다.
- 문구마다 **한 줄씩 따로 복사**합니다. 칸이 다 다르니 통째로 복사할 일이 없습니다.

### 소식 글감 — 견본이 아니라 우리 재료로

4주치를 만들되, **수집한 시설·가격·리뷰·진행 이벤트**를 넣습니다.
3주차는 손님이 리뷰에서 가장 많이 쓴 말을 주제로 세웁니다.
제목은 40자 제한이 있어서 **몇 자인지 같이 적습니다.**

```
3주차 - 회원 후기 - 가격  (제목 21자 / 40자 제한)
"가격 때문에 오셨다는 회원님이 많습니다"
- 리뷰에서 "가격"을 19회 언급하셨습니다. 손님이 이미 말한 강점이라 반응이 좋습니다
- 얼굴 없는 사진으로. 숫자(기간, 횟수)가 들어가면 더 읽힙니다
```

달이 바뀌면 소재도 바뀝니다. 1월과 7월에 같은 글을 올릴 수는 없기 때문에,
**이번 달에 쓸 만한 계절 소재**를 한 줄 더 붙여 드립니다.

### 손님 유형 — 한 명이 아니라 여럿, 리뷰에서 읽습니다

소개글 첫 줄은 "이 글이 내 얘기인가"를 가릅니다. 그래서 누구에게 쓰는지가 먼저입니다.
그런데 그 대상을 **사장님이 자랑하고 싶은 것**으로 정하면 빗나갑니다.

수집한 리뷰 본문에서 손님이 실제로 쓴 말을 셉니다.

```
가격        19회   가격, 합리, 만원
처음 시작    10회   처음, 초보, 시작, 몰라
시설·청결     9회   쾌적, 넓, 시설
친절·상담     8회   친절, 상담
혼자 조용히    6회   혼자, 조용, 집중

→ "가격부터 따져보는 분" 을 기본으로 선택
→ 첫 줄: "가격이 얼마인지부터 궁금하시죠"
```

화면에도 **왜 그렇게 골랐는지 근거를 그대로 밝힙니다.** 6가지 중에서 바꾸실 수 있습니다.

**다만 손님은 한 종류가 아닙니다.** 첫 줄은 한 명에게 걸되, 나머지 손님의 고민은
본문에서 번호를 매겨 따로 답합니다. 각 답에는 리뷰에서 실제로 나온 말을 근거로 붙입니다.

```
[혹시 이런 고민 때문에 망설이고 계신가요]
1. 기구를 어떻게 쓰는지 몰라 망설여지시나요?
   처음 오시는 분께는 기구 사용법과 동선을 직접 알려드립니다.
   실제로 리뷰에도 '처음', '초보' 같은 말이 자주 나옵니다.
2. 혼자 가기 눈치 보이시나요?
   여성 전용존을 따로 두었습니다. ... 리뷰에도 '혼자', '조용' 같은 말이 자주 나옵니다.
3. 퇴근이 늦어 시간이 안 맞으시나요?
   24시간 운영합니다. ... 리뷰에도 '밤', '퇴근' 같은 말이 자주 나옵니다.
```

- 함께 다룰 손님은 **체크박스로 고릅니다.** 리뷰 언급 횟수가 칩에 같이 나옵니다.
- **고민 목록에서 답한 주제는 위쪽 시설 칸에서 뺍니다.** 같은 말을 두 번 하면
  글만 길어지고 읽는 사람은 지루해집니다.
- 1,800자를 넘으면 인용 리뷰를 먼저 줄이고, 그래도 넘치면 고민 개수를 줄입니다.

### 리뷰 답글 — 그 리뷰를 읽었다는 게 드러나야 합니다

처음 만든 것은 **세 리뷰에 거의 같은 답글**이 나왔습니다. 주제를 하나만 골라 한 문장만
갈아 끼우는 구조였기 때문입니다. 손님은 복붙 답글을 바로 알아봅니다. 그리고
*"공부하느라 앉아만 있어 어깨가 아프다"* 는 리뷰에 *"기구 사용법을 알려드리는 건 당연한 일"*
이라고 답하면, 그 답글은 **리뷰를 안 읽었다는 증거**가 됩니다.

넷을 고쳤습니다.

1. **주제를 하나가 아니라 여럿** 뽑고, 앞 답글과 겹치면 다음 주제로 넘깁니다
2. **그 리뷰가 무슨 상황인지 한 줄로 받습니다** — 손님 문장을 통째로 따서
   *"...라고 해 주신 부분"* 하고 되돌려 주던 때가 있었는데, 읽었다는 걸 증명하려는
   짓이라 로봇 티만 났습니다. 사람은 그렇게 말하지 않습니다. 인용 부호 없이,
   그 얘기를 들은 사람이 자연스럽게 할 법한 말로 받습니다
3. **인사와 마무리를 돌려 씁니다** — 세 답글이 같은 문장으로 시작하지 않게
4. **별점에 따라 톤을 바꿉니다** — 1~2점에 "기분이 좋습니다"는 재앙입니다

주제는 11가지입니다. 가격 · 시설·청결 · 친절·상담 · 혼자·조용 · 시간대 · PT·자세 ·
처음·초보 · **통증·자세** · **체중·다이어트** · **동반·지인** · **주차·위치**.
뒤의 넷은 실제 리뷰에 자주 나오는데 못 알아듣던 주제라 새로 넣었습니다.

```
[3] 실제 리뷰 - 공부하느라 계속 앉아만 있으니까 어깨랑 허리도 아프고 자세가...
읽어낸 주제: 통증, 자세, PT, 자세
답글 (252자): 반갑습니다, ○○입니다. 이렇게 후기까지 남겨 주셔서 감사합니다.
"공부하느라 계속 앉아만 있으니까 어깨랑 허리도 아프고..."라고 해 주신 부분,
감사히 읽었습니다. 아프신 부위가 있으시면 그 부위에 무리 가는 동작부터 빼고
잡아 드립니다. 참고 하시면 더 나빠집니다. 자세는 계속 봐 드리겠습니다.
무게보다 자세가 먼저입니다. ...
```

**새로 달린 리뷰는 붙여넣으세요.** 수집한 리뷰는 과거 것이라, 오늘 달린 리뷰에는
그 칸이 필요합니다. 별점을 고르고 만들면 **세 가지 후보**가 나오고 각각 글자수가 붙습니다.
1~2점을 고르면 사과로 시작하는 답글만 나오고, *"하루 안에 다세요"* 안내가 함께 뜹니다.

**답글 길이 · 심을 키워드 · 끝인사**를 고르실 수 있습니다.

| | |
|---|---|
| 길이 | 짧게 2~3문장 / 중간 4~5문장 / 길게 6~7문장 |
| 심을 키워드 | 목표 키워드·대표키워드에서 하나. 답글도 플레이스 안 텍스트입니다 |
| 끝인사 | **한 번만 적으면 모든 답글 끝에 붙습니다.** 기기 사이에도 따라갑니다 |

### 못 알아들었으면 못 알아들었다고 말합니다

여기가 AI 도구에는 없는 자리입니다. **AI는 무엇이든 그럴듯하게 써 주기 때문에,
못 알아들었다는 사실 자체가 안 보입니다.** 사장님은 엉뚱한 답글을 그대로 붙여넣게 됩니다.

저희는 주제 사전에 안 걸리면 그렇게 적고, **그 자리에서 AI 지시문으로 넘길 길**을 줍니다.

```
읽어낸 주제  못 알아들었습니다

이 리뷰는 저희가 아는 주제에 안 걸렸습니다. 아래 답글은 무난하지만
이 리뷰에 대한 답은 아닙니다. 이런 리뷰는 AI에게 넘기시는 편이 낫습니다.
                                    [이 리뷰로 AI 지시문 만들기]
```

누르면 **리뷰 본문 + 별점 + 길이 + 심을 키워드 + 끝인사 + 우리 가게 정보**를 전부 담은
지시문이 만들어집니다. 쓰시는 AI 채팅에 붙여넣으면 됩니다. **돈은 들지 않습니다.**

### 문장 자연스러움은 AI가 낫습니다 — 감추지 않습니다

저희 답글은 **정해둔 문장을 조합해서** 만듭니다. 바로 쓰기엔 좋지만 사람이 쓴 맛은
덜합니다. **한 편씩 AI를 돌리는 도구가 문장에서는 이깁니다.** 그건 구조 차이라
템플릿을 아무리 다듬어도 뒤집히지 않습니다.

그래서 답글 아래에 **항상** AI 지시문으로 넘기는 길을 열어 둡니다. 못 알아들었을 때만이
아니라 언제든지요. 지시문에는 리뷰 본문·별점·길이·심을 키워드·끝인사·우리 가게 정보가
전부 들어갑니다. 쓰시는 AI 채팅에 붙여넣으면 됩니다. **돈은 들지 않습니다.**

두 번째 주제도 **확실히 걸렸을 때만** 붙입니다. 예전에는 단어 하나 스친 정도로 붙여서,
어깨가 아프다는 리뷰에 *"여성 전용존을 따로 두었습니다"* 가 딸려 나왔습니다.
확실하지 않으면 없는 얘기를 끌어오는 대신 **같은 주제를 한 걸음 더** 이어 갑니다.

### AI에게 직접 시킬 수도 있습니다 (선택, 키 필요)

서버에 Anthropic API 키를 넣으면 도구 안에서 바로 AI가 씁니다. **키가 없으면
지금까지처럼 무료 방식으로 돌아갑니다** — 코드가 있어도 잠들어 있습니다.

**서버가 요청을 다시 짓습니다.** 예전에는 받은 요청을 그대로 흘려보냈는데,
그러면 이 주소를 아는 사람이 `model`과 `max_tokens`를 바꿔 보낼 수 있었습니다.
제일 비싼 모델로 최대 길이를 계속 때리면 몇 분 만에 큰돈이 나갑니다.
접속 키만으로는 못 막습니다.

| 막는 것 | 어떻게 |
|---|---|
| 비싼 모델 강제 | **서버가 모델을 정합니다.** 답글=Haiku, 소개글=Opus. 클라이언트가 뭘 보내든 무시 |
| 길이 폭탄 | `max_tokens` 서버 상한 고정 (2,000 / 4,000) |
| 무한 호출 | **하루 호출 한도** (`AI_DAILY_CAP`, 기본 40회). 넘으면 앤트로픽으로 아예 안 나갑니다 |
| 모르는 사이 소진 | 오늘 몇 번 썼는지 화면에 표시 |
| 이상한 요청 | 빈 내용 · 2만자 초과 · 깨진 JSON 은 400 |

일마다 모델을 나눕니다. (100만 토큰당) **Haiku $1/$5 · Opus $5/$25** — 다섯 배 차이입니다.

**답글은 고르실 수 있습니다.**

| | 언제 |
|---|---|
| 기본 (Haiku · 약 10원) | 칭찬 리뷰. 대부분 여기서 충분합니다 |
| 좋은 것 (Opus · 약 50원) | **불만 리뷰(1~2점), 비꼬는 리뷰.** 말의 결을 읽어야 하는 자리 |

소개글은 길고 오래 쓰는 글이라 항상 좋은 쪽입니다.

**횟수만 세면 안 됩니다.** 같은 10회라도 모델에 따라 다섯 배 차이라, 오늘 쓴
**금액도 함께** 세서 화면에 적습니다 — `오늘 3/10회 · 약 71원`.
환율은 `USD_KRW` 환경변수로 바꿀 수 있습니다 (기본 1450). 금액은 추정이니
실제 잔액은 콘솔에서 확인하세요.

**나온 글은 AI가 썼어도 우리 일곱 가지 잣대로 검사합니다.** 그건 저희만 합니다.

> ⚠️ **키를 넣기 전에 `ACCESS_KEY`를 반드시 바꾸세요.** 지금 값이 노출돼 있으면
> 주소를 아는 사람이 사장님 돈으로 AI를 돌립니다. 하루 한도가 있어 피해는
> 한도 안에서 끝나지만, 애초에 막는 편이 낫습니다.

### 답글 지시문은 순위로 이어지는 세 갈래에 맞춰 짰습니다

**답글이 순위를 직접 올린다는 네이버 공개 근거는 없습니다.** 다만 이어지는 길은 셋입니다.

1. 답글은 **플레이스 안의 글**이라 검색어와 맞물릴 재료가 됩니다 (적합도)
2. 다음 손님이 답글을 **읽느라 머뭅니다** (인기도로 흔히 이야기되는 신호)
3. 그 손님이 **문의·방문으로 넘어갑니다** (이건 확실히 우리 지표입니다)

그래서 지시문은 *"키워드를 넣어라"*가 아니라 **순서를 못박습니다.**

> 먼저 읽히는 글을 쓰고, 그다음에 검색어가 한 번 들어가게 하세요.
> 반대로 하면 둘 다 잃습니다.

| 시키는 것 | 왜 |
|---|---|
| 이 리뷰에만 할 수 있는 말을 하라 | 어느 리뷰에 붙여도 되는 문장이면 안 읽힙니다 |
| 따옴표 인용 금지 | 사람은 상대 말을 따옴표로 되돌려 주지 않습니다 |
| 리뷰에 나온 **사람 이름을 부르라** | 트레이너 이름이 나오면 전달하겠다고 |
| 다음 손님의 **망설임 하나를 지우라** | 가격·주차·분위기·시간·초보 중 그 리뷰와 이어지는 하나 |
| `지역 업종` 표현을 **3개 중 1~2개에만** | 전부에 넣으면 반복으로 보입니다 |
| 셋을 서로 다른 각도로 | 직접 답 / 다음 손님 궁금증 / 짧고 담백 |

**별점이 낮으면 지시문 자체가 바뀝니다.**

```
별 1~2개 →  변명 금지 · 사과 → 무엇을 어떻게 → 직접 연락 요청
            "확인해 보겠습니다"로 끝내지 말 것. 언제까지 무엇을 할지 적을 것
            홍보 문구와 키워드 절대 금지 ← 사과할 자리에 광고를 넣으면 그게 다음 손님에게 보입니다
```

### 답글에 쓸 수 있는 "확인된 사실"을 목록으로 넘깁니다

은코치 답글과 실제로 붙여 봤고, **한 항목에서 크게 졌습니다.**

> 저희가 합리적인 가격을 유지할 수 있는 이유는 멤버분들의 오랜 신뢰 덕분입니다

이 문장은 천안 어느 헬스장에 갖다 붙여도 그대로 맞습니다. 읽는 사람이 얻는 게 없습니다.

원인은 재료가 아니라 지시문이었습니다. 시설·리뷰 수·오시는 길을 **이미 넘기고 있었는데**
지시문이 "우리 강점 한 가지를 넣으세요"라고만 해서, AI 가 빈말로 채웠습니다.

지금은 확인된 사실만 추려 목록으로 넘깁니다.

```
[답글에 쓸 수 있는 사실] - 확인된 것만 적었습니다. 이 목록 밖은 지어내지 마세요.
- 주차 가능
- 샤워실
- 24시간 운영
- 인바디 측정
- 1개월 이용권 89,000원
- 방문자 리뷰 4,673개 · 평점 4.97점
- 봉명역 2번 출구 도보 11분
- 쌍용패션거리 정류장 도보 2분
```

**메뉴 칸에 적어 두신 이름이 제일 값진 재료입니다.** 지금까지 "메뉴 19개"라는 숫자만 쓰고
이름은 버리고 있었습니다. 거기에 이런 것이 들어 있었습니다.

```
여성전용(우먼존) 24시이용권 · 스미스머신 파워렉 6대 · 프리미엄 웨이트머신 100종
각종 유산소 머신 21대 · 천국의 계단 4대 · 기구필라테스 무료이용 · 인바디 무료이용
```

**다른 헬스장이 쓸 수 없는 문장이 여기 다 있습니다.** 이모지는 네이버 입력칸에서 막히므로
떼고 넘깁니다.

그리고 **빈말을 이름으로 지목해 금지**합니다 — "신뢰 덕분입니다 / 최선을 다하겠습니다 /
더 좋은 환경을 만들겠습니다 / 보답하겠습니다". 판별법도 함께 줍니다:
**그 문장에서 우리 가게 이름을 빼고 다른 헬스장 이름을 넣어도 말이 되면 실패입니다.**

**소식(피드) 본문도 읽습니다.** 개업 연차는 네이버의 어느 필드에도 없습니다.
사장님이 소식에 쓰신 문장에만 있습니다.

> "쌍용동 헬스장에서 **28년째** 같은 자리를 지키고 있는 MTO 피트니스 쌍용점입니다"

`/feed` 페이지는 원래 가져오고 있었는데 본문을 버리고 있었습니다. 지금은 소식 6건을
지시문에 싣고, 거기서 `N년째 / N년간 / N년 전통` 을 찾아 **"28년째 운영 중"** 이라는
사실 한 줄로 만듭니다. `1998년 개업`, `2026년 8월` 같은 **연도는 연차로 읽지 않습니다** —
"2026년째 운영 중"이 되면 거짓말이 됩니다.

### 우리만 아는 사실 — 네이버에 없는 것을 담아 둡니다

수집으로는 시설·가격·리뷰 수까지만 옵니다. **트레이너 수와 자격, 회원 구성, 주변 직장은
어디에도 없습니다.** 그래서 답글이 계속 밋밋해집니다.

`1 플레이스 정보` 에 **우리만 아는 사실** 칸을 뒀습니다. 한 줄에 하나씩 적으면
답글·소개글·소식이 전부 이걸 재료로 씁니다. 한 번만 적으면 됩니다.

```
트레이너 4명 모두 생활스포츠지도사 2급 이상
순천향병원 3교대 근무자 회원이 많습니다
락커는 대기 없이 바로 배정됩니다
```

몇 줄을 읽었는지 칸 밑에 표시합니다. 적은 것이 실제로 쓰이는지 확인할 방법이 없으면
이 칸은 안 채우게 되기 때문입니다. 직접 적으신 사실은 **재료 목록 맨 앞**에 놓입니다.

**검색어를 직접 지정하시면 3개 답글 전부에 넣습니다.** 예전에는 "3개 중 1~2개에만"이었는데,
사장님은 그중 **하나만 골라서** 실제로 답니다. 빠진 것을 고르시면 헛일이 됩니다.
자동으로 추정한 검색어일 때만 1~2개 규칙을 씁니다.

**재료가 3개 미만이면 답글 밑에 그렇게 적습니다.** 재료 없이 만든 답글은 어느 도구를 써도
어느 헬스장에나 붙는 글이 됩니다. 그 사실을 감추면 사장님은 도구가 원래 이 정도인 줄 아시게 됩니다.

### 마크다운은 걷어냅니다

네이버 입력칸은 마크다운을 못 읽습니다. `**강조**` 를 넣으면 굵게 표시되는 게 아니라
**별표가 글자 그대로 화면에 박힙니다.** 그런데 네이버는 별표를 막지 않기 때문에
금지문자 검사에도 안 걸립니다. 받아 주기 때문에 더 나쁩니다.

지시문에 "마크다운 쓰지 마세요"라고 못박아 뒀지만 AI 는 습관처럼 씁니다.
그래서 출력 단계에서 `**` `__` `##` `>` 를 걷어내고 **안쪽 글은 살립니다.**
검사에서도 몇 곳 있었는지 따로 셉니다.

### 점검표가 우리 생성기 편을 들고 있었습니다

`우리 강점이 한 가지 들어갔다` 항목의 판정이 이랬습니다.

```js
ok: REPLY_TOPIC.some(x => t.includes(x.line(o).slice(0, 12)))
```

**우리 템플릿 문장의 앞 12글자가 들어 있는지**를 봅니다. 우리 생성기는 그 문장을 직접
쓰니 늘 통과하고, AI 는 자기 말로 쓰니 **영원히 통과할 수 없었습니다.**
품질이 아니라 "내 문장을 베꼈나"를 재고 있었습니다.

실제로 같은 리뷰에서 이렇게 갈렸습니다.

| | AI 답글 | 자동 답글 |
|---|---|---|
| 우리 강점이 한 가지 들어갔다 | ✗ | ○ |
| 우리 가게에만 쓸 수 있는 말 | **○** 무료 PT 상담, 인바디 | **✗** 사실 하나도 없음 |

정반대입니다. **아래쪽이 맞는 판정입니다.** 그래서 위 항목을 지웠습니다.

그리고 `다시 오실 이유가 있다` 는 우리 생성기가 늘 쓰는 몇 마디만 찾고 있어서,
같은 뜻의 다른 표현을 못 알아봤습니다. 범위를 넓히고, 걸렸을 때
**"인사로만 끝났습니다 - 다시 오시라는 말이 없습니다"** 라고 이유를 적습니다.

### 글자가 나오는 대로 보여줍니다 (스트리밍)

예전에는 AI 가 다 쓸 때까지 5~10초 동안 화면이 조용했습니다. **사장님이 멈춘 줄 알고
버튼을 다시 누르면 한도만 두 번 깎입니다.**

지금은 첫 글자가 1초 안에 뜨고 이어서 채워집니다.

한도와 모델 판정은 `/api/ai` 와 **똑같은 함수 하나**를 씁니다. 한쪽으로만 우회되면
안 되기 때문입니다. 클라이언트가 `model: "claude-opus-5"` 를 보내도 서버가 무시합니다.

> 중간 프록시가 응답을 모아서 한 번에 내보내면 스트리밍이 아니게 됩니다.
> `x-accel-buffering: no` 를 붙여 막았습니다.

### 블로그 후기 주소는 수집할 때 딸려 옵니다

손으로 옮겨 적으실 필요가 없습니다. 플레이스 응답의 `FsasReview.url` 에
주소가 그대로 들어 있습니다.

```
url = https://m.blog.naver.com/ojh3529/224359479096
url = https://m.blog.naver.com/jiyun0361/224352038257
url = https://m.blog.naver.com/ezroc4beat/224352036363
```

수집하면 **"플레이스에 걸린 후기 3개를 찾았습니다"** 와 함께
`본문 3개 한 번에 가져오기` 버튼이 나옵니다.

본문을 받아 오면 **수집 때 들어온 앞부분 조각은 버립니다.** 안 버리면 같은 얘기가
재료에 두 번 실리고, 다섯 자리를 조각이 차지해서 정작 다른 글이 밀려납니다.

### 블로그 후기 주소를 직접 넣을 수도 있습니다

플레이스 페이지에 실리는 블로그 후기는 **앞부분만** 옵니다. 주소를 아는 후기는
본문을 통째로 읽을 수 있고, 거기에 `펙덱플라이`, `랫풀다운`, `천국의 계단`처럼
**네이버 어느 필드에도 없는 말**이 적혀 있습니다.

`1 플레이스 정보` 에 **블로그 후기 주소** 칸을 뒀습니다. 넣으면 답글·소개글 재료가 됩니다.

> 네이버 블로그는 본문이 iframe 안에 있어서 겉 주소를 읽으면 빈 껍데기만 옵니다.
> `blog.naver.com/아이디/글번호` 를 넣으면 본문이 실제로 있는
> `PostView.naver?blogId=...&logNo=...` 로 바꿔서 읽습니다.

태그·스크립트·스타일은 걷어내고 글만 남기며, `&lt;` 같은 기호는 되돌립니다.
같은 글을 두 번 넣어도 하나로 셉니다. 비공개 글이면 그렇다고 말합니다.

### 불만 리뷰(1~2점)를 실제로 읽습니다

여기가 제일 오래 방치돼 있었습니다. 예전 코드는 이랬습니다.

```js
if(star <= 2) return { topics:[], text: tail(RP_LOW(N, A, S)) };
```

**별점만 보고 고정 문장 하나를 내보냈습니다.** 손님이 무엇 때문에 화가 났는지
읽지도 않았고, 그러면서 이렇게 답했습니다.

> 말씀해 주신 내용은 저희가 놓치고 있던 부분이 맞습니다.

**보지도 않고 먼저 잘못을 인정하는 문장입니다.** 부당한 리뷰에도 그렇게 답하면
그 문장이 그대로 공개 증거가 됩니다.

지금은 불만 주제 10가지를 읽습니다.

| 주제 | 무엇을 받는가 | 무엇을 하겠다고 하는가 |
|---|---|---|
| 혼잡·대기 | 기구 앞에서 기다리시게 한 점 | 몰리는 시간대를 다시 보고 배치를 손보겠습니다 |
| 청결 | 청소가 닿지 않은 곳이 있었던 점 | 오늘 확인하고 점검 주기를 다시 잡겠습니다 |
| 기구 고장 | 운동이 끊긴 점 | 고치기 전까지 쓰지 못한다는 표시를 붙이겠습니다 |
| 응대 | 응대가 불편하게 느껴지신 점 | 어느 시간대 일인지 확인하고 직원과 이야기하겠습니다 |
| 환불·계약 | 금액 문제로 마음 상하신 점 | 데스크로 연락 주시면 바로 처리하겠습니다 |

나머지는 소음·매너 / 온도·환기 / 락커·샤워 / 주차 / 권유·영업입니다.

**못 알아들으면 아는 척하지 않습니다.** "별로였어요" 같은 리뷰에는
잘못을 단정하는 대신 무엇이 있었는지부터 여쭙습니다. 사과는 그대로 합니다.

### 불만 답글은 잣대가 다릅니다

칭찬 답글 잣대를 그대로 대면 **사과할 자리에 "키워드를 넣으세요",
"우리 강점을 넣으세요"라고 시키게 됩니다.** 다음 손님이 제일 싫어하는 답글입니다.

1~2점일 때는 점검 항목이 통째로 바뀝니다.

```
O 사과가 먼저 나온다
O 무엇이 불편했는지 짚었다
O 무엇을 하겠다고 적었다        ← "확인해 보겠습니다"로 끝나면 걸립니다
O 직접 연락할 길을 열었다
O 변명이 없다                   ← "그날따라 바쁜 시간대라"를 잡아냅니다
O 홍보가 없다
O 검색어를 심지 않았다
O 지킬 수 있을지 모르는 약속이 없다
O 네이버 금지문자 0개
```

업체명이 `쌍용동헬스장 MTO피트니스`라서 이름만 대도 검색어를 심은 것으로
잡히던 것도 고쳤습니다. 이름은 첫머리에 당연히 나오는 것이라 심은 게 아닙니다.

### 3점은 아쉬운 쪽을 먼저 받습니다

3점은 좋았던 점과 아쉬운 점이 섞여 있습니다. 예전에는 아쉬움을 받아 놓고
칭찬용 문장(`기구 점검은 매일 하고 있습니다`)으로 이어서, 읽으면 변명이 됐습니다.
지금은 불만이 잡히면 그것을 먼저 받고 좋았던 점은 뒤에 한 줄만 둡니다.

### 블로그 후기 본문도 재료로 씁니다

블로그 후기는 방문자 리뷰보다 길고 구체적입니다. **기구 이름이나 동선처럼
네이버 기본 필드에 없는 것이 여기 적혀 있습니다** — `펙덱플라이`, `랫풀다운`이
그랬습니다. 수집은 하고 있었는데 아무 데도 쓰지 않고 있었습니다.

### 지시문에 규칙이 너무 많았습니다

같은 AI 를 쓰는데 왜 문장이 뻣뻣한지 재 봤습니다.

```
지시문 전체 : 3,346자 · 104줄
규칙 줄     : 56개
금지 문장   : 16줄
대괄호 묶음 : 12개
```

**AI 가 56개짜리 점검표를 통과하는 데 힘을 쓰고 있었습니다.** 그러니 점검표를
통과하는 글, 즉 심사 서류 같은 문장이 나옵니다.

세 가지를 했습니다.

1. **코드가 이미 막는 것을 지시문에서 뺐습니다.** 이모지·가운뎃점·마크다운은
   출력 단계에서 `naverSafe` 가 어차피 지웁니다. 네 줄을 한 줄로 줄였습니다.
2. **겹치는 묶음을 합쳤습니다.** `[문체]` 와 `[읽는 맛]`, 다섯 줄짜리 설명은 한 줄로.
3. **규칙 대신 예시를 넣었습니다.** 이게 제일 큽니다.

```
[이런 답글을 원합니다 - 규칙을 스무 개 읽는 것보다 이걸 한 번 보는 게 빠릅니다]
  자주 찾아주셔서 감사합니다. 6개월로 끊고 꾸준히 오시는 분들 덕분에 지금 가격을
  유지하고 있습니다. 기구는 계속 늘리는 중이라 스미스머신 파워렉만 6대 있습니다.
  저녁에도 기다리는 일이 거의 없으실 겁니다. 다음에 오시면 편하게 말씀 걸어 주세요.
왜 괜찮은가 - 손님이 쓴 말을 받았고, 우리만 쓸 수 있는 숫자가 들어갔고,
다음 손님이 궁금해할 것을 답했고, 문장 길이가 섞여 있고, 마지막이 초대입니다.
```

예시를 **넣고도** 규칙은 56 → 49줄, 금지 문장은 16 → 12줄로 줄었습니다.

### 읽는 맛 - 조립한 티가 나는 자리

어미는 이미 섞여 있었습니다. 진짜 조립 티는 다른 데 있었습니다.

```
이용권은 기간별로 나눠 두었습니다. 완초자 (초보자) PT 무료까지 갖춰 두었습니다.
              어미 충돌 ↑                    메뉴판 글자를 날것으로 ↑
```

**메뉴 이름을 문장에 맞게 다듬습니다.**

```
완초자 (초보자) PT 무료   →  완초자(초보자) PT 무료
프리미엄 웨이트머신100종  →  프리미엄 웨이트머신 100종
```

**앞 문장과 어미가 겹치지 않는 틀을 고릅니다.** `…나눠 두었습니다. …갖춰 두었습니다.` 가
이어지면 읽는 사람이 바로 압니다.

점검표에 **`같은 말투가 이어지지 않는다`** 를 넣었습니다. 같은 어미가 세 문장 이어지면
걸리고, 어느 말이 몇 번 이어졌는지 적어 줍니다. AI 가 쓴 글에도 똑같이 적용됩니다.

AI 지시문에도 `[읽는 맛]` 항목을 넣었습니다 — 문장 길이 섞기, 같은 어미 3연속 금지,
시설 이름을 나열하지 말고 앞 문장과 잇기.

> **다만 여기까지가 조립식의 한계입니다.** 문장을 정말 사람처럼 쓰는 것은
> 틀을 아무리 다듬어도 AI 를 못 이깁니다. 그 사실은 화면에도 적어 두었습니다.

### 따뜻하면서 홍보도 되게 - 순서가 전부입니다

생색을 없애려다 **시설 이름까지 지웠습니다.** 그러면 플레이스를 보는 다음 사람에게
아무것도 안 남습니다. 둘 다 잡는 방법이 있습니다.

**시설을 스펙으로 말하지 말고, 그분 마음에 대한 답으로 내놓는 것**입니다.

```
나쁜 예  저희는 여성전용 우먼존을 별도로 운영하고 있습니다.
         → 스펙입니다. 그분 얘기가 없어서 자랑으로 읽힙니다.

좋은 예  혼자 조용히 하고 싶으셨던 그 마음, 저희가 우먼존을 따로 뺀 이유이기도 합니다.
         눈치 안 보고 편하게 쓰시면 됩니다.
         → 같은 시설인데 그분 마음에서 출발했습니다.
           읽는 다른 사람에게도 그대로 전해집니다.
```

지시문에 순서를 못박았습니다.

1. 그분이 쓴 마음이나 상황을 먼저 알아준다
2. **그래서** 우리가 이렇게 해 두었다고 잇는다
3. 그러니 이렇게 하시면 된다고 닫는다

**시설 이름은 넣습니다.** 다만 반드시 그분 이야기에 붙여서. 따로 떼서 나열하는
순간 안내판이 되고, 그때부터 생색입니다. 두 개 넘게 넣는 것도 나열입니다.

무료 답글도 같은 순서로 만듭니다 — `그래서 스미스머신 파워렉 6대 뒀습니다.
편하실 때 쓰시면 됩니다.`

### 말투를 부드럽게 풀었습니다

`…습니다`로만 끝내면 공문서가 됩니다. `…네요`, `…하실 거예요`, `…이더라고요` 를
섞게 했습니다. 상담원 말투(`고객님`, `안내드립니다`)는 그대로 금지입니다.

> 사실 문장이 두 문장짜리가 되면서 어미 충돌이 다시 생겼습니다.
> 앞 문장과 부딪히는 것이 **마지막이 아니라 첫 문장**이라 검사하는 자리를 옮겼습니다.

### 답글은 후기를 써 주신 그분께 드리는 인사입니다

**전제를 잘못 깔고 있었습니다.** 지시문 맨 앞이 이랬습니다.

> 리뷰를 쓴 손님이 아니라 그 답글을 **읽는 다음 손님을 위한 글**입니다.

이 한 줄이 나머지를 다 끌고 갑니다 — 시설 자랑, 검색어 심기, "다음 손님의 망설임".
그래서 나온 답글이 **생색으로 읽혔습니다.** 사장님 지적이 맞았습니다.

> "기본적으로 리뷰 답글은 등록해주셔서 감사한 고객님을 향한 메시지"

초점을 돌렸습니다.

| | 전 | 지금 |
|---|---|---|
| 누구에게 | 다음 손님 | **후기를 써 주신 그분** |
| 주어 | 저희는 이걸 갖췄습니다 | **이건 이렇게 쓰시면 됩니다** |
| 사실 목록 | 자랑거리 | **그분이 앞으로 편하시라고 알려 드리는 것** |
| 망설임 | 다음 손님의 망설임을 지운다 | **그분이 앞으로 겪을 불편을 먼저 챙긴다** |
| 검색어 문장 | 처음 알아보시는 분들은 시설을 한 번 보고… | **여러 곳 중에 여기를 골라 주신 것이 늘 고맙습니다** |
| 사실 얹는 말 | 스미스머신 6대까지 **갖춰 두었습니다** | 스미스머신 6대 있으니 **편할 때 쓰시면 됩니다** |

그리고 두 가지를 새로 시킵니다.

- **무엇이 고마운지 적으세요.** 형식적인 "감사합니다" 한 마디 말고,
  등록해 주신 것, 시간 내어 글을 써 주신 것, 다시 찾아 주신 것.
- **그분이 잘하고 계신 것을 짚어 주세요.** 칭찬은 우리 자랑보다 훨씬 오래 남습니다.

점검표에 **`우리 자랑이 아니라 그분 이야기다`** 를 넣었습니다.
`저희·우리`가 세 번 넘게 나오거나 손님 얘기보다 많으면 걸립니다.
AI 가 쓴 글에도 똑같이 적용됩니다.

### 한 리뷰에 여러 얘기가 있으면 다 받습니다

실제로 이런 리뷰가 왔습니다.

> 다이어트를 위해 운동을 시작하려고 **재등록**하게 되었습니다. **혼자 조용히** 운동하기 위해
> 혼자 등록했고 **3개월 할인**받아 저렴하게 등록했네요. **24시 영업**이라 좋습니다.

다섯 가지가 들어 있는데 우리는 **"혼자" 하나만** 답했습니다. 이유가 셋이었습니다.

**① 주제를 걸린 횟수로만 골랐습니다.** "혼자"가 두 번 나오니 이겼습니다.
`다이어트`, `24시`, `재등록`처럼 **긴 말은 한 번만 나와도 그 리뷰의 주제**입니다.
이제 길이도 함께 봅니다.

**② 재등록이라는 주제가 아예 없었습니다.** 손님이 줄 수 있는 제일 큰 칭찬인데
목록에 없어서 읽고도 그 말을 못 했습니다. 넣었고, 다른 주제와 같이 걸리면
이쪽을 먼저 받습니다.

**③ 두 번째 주제 하나만 썼습니다.** 이제 2번 답글이 **세 개까지** 받습니다.

### 손님이 여성이라고 추측하지 않습니다

리뷰에 여성이라는 단서가 없는데 **"여성 전용존도 따로 두었습니다"** 라고 답하고
있었습니다. 남성 회원께는 엉뚱한 답글입니다.

주제 문장에서 막았더니 이번엔 **메뉴 목록으로 새어 나왔습니다**
(`여성전용(우먼존) 24시이용권도 있으니…`). 두 군데 다 막았습니다.
리뷰에 `여성 / 여자 / 아내 / 딸` 같은 말이 있을 때만 꺼냅니다.

### 재등록한 분께 "처음이 제일 어렵다"고 하지 않습니다

이미 다녀 보고 다시 오신 분입니다. `처음·초보` 주제가 같이 걸려도 쓰지 않습니다.

### 답글 3개는 뼈대가 서로 다릅니다

예전에는 세 답글이 **같은 뼈대에 인사말과 사실 한 줄만 바꿔 끼우는** 구조였습니다.
그래서 가운데가 글자 하나까지 똑같은 글 세 개가 나왔습니다.
사장님은 그중 **하나만 골라** 다십니다. 셋이 비슷하면 셋을 줄 이유가 없습니다.

지금은 이렇게 나눕니다.

| | 무엇을 하는 답글인가 | 길이 |
|---|---|---:|
| 1번 | 손님이 말한 그 얘기에 바로 답한다 | 178자 |
| 2번 | 다음 손님이 궁금해할 것을 한 줄 더 얹는다 | 271자 |
| 3번 | 짧게, 우리 사실 하나만 두고 끝낸다 | 140자 |

검색어를 심는 문장은 **2번에만** 둡니다. 셋에 다 넣으면 광고로 읽힙니다.
(목표 키워드 자체는 업체명에도 들어 있어 셋 다 들어갑니다.)

### 주제에 안 맞는 사실은 붙이지 않습니다

가격 이야기에 **"에어컨9대/선풍기9대 가동중"** 이 붙어 나온 적이 있습니다.
메뉴 칸에서 아무거나 골랐기 때문입니다. 읽는 사람은 "그래서?"가 됩니다.

주제마다 어울리는 사실을 먼저 고릅니다.

```
혼자 조용히 → 여성전용(우먼존), 스트레칭실
새벽·교대   → 365일 24시 이용권
처음·초보   → 완초자 PT 무료, 인바디
가격        → 웨이트머신 100종, 유산소 21대 (이 값에 이만큼)
```

**공지(에어컨 가동중)와 이벤트(하루특가, 5개월 15만원)는 아예 뺍니다.**
공지는 자랑거리가 아니고, 이벤트를 답글에 넣으면 광고가 됩니다.

### 알맹이 없는 문장으로 때우지 않습니다

`이용권 금액은 메뉴에 그대로 적어 두었습니다` — 금액을 못 가져왔을 때 나오던
문장입니다. **"메뉴 보세요"는 답글이 아닙니다.** 답글 한가운데를 빈 문장이
차지하고 있었습니다. 지금은 금액을 아는 경우에만 금액을 말합니다.

> **참고** — 네이버 메뉴 19개에 **금액이 하나도 안 들어가 있습니다.**
> 메뉴 이름만 있고 가격칸이 비어 있습니다. 스마트플레이스에서 이용권 금액을
> 넣으시면 답글과 소개글이 훨씬 구체적으로 나오고, 진단의
> `이용권·PT 가격을 공개했다`(6점)도 함께 채워집니다.

### 지킬 수 있을지 모르는 약속은 넣지 않습니다

답글은 몇 년씩 남습니다. **지금 지킬 수 있어도 나중에 못 지키게 되면 그 답글이
그대로 증거가 됩니다.** 가격이 제일 위험합니다.

자동 답글이 이런 문장을 쓰고 있었습니다.

```
가격은 앞으로도 올리지 않고 89,000원 기준을 지키겠습니다.
등록하실 때 안 보이던 비용이 나중에 붙는 일은 없게 하겠습니다.
주차 공간은 계속 확보해 두겠습니다.
기구가 고장 나면 표시를 붙여 두고 그날 안에 손봅니다.
```

물가가 오르면 첫 줄이 사장님을 거짓말한 사람으로 만듭니다. 두 번째 줄은
"숨은 비용이 있었나" 하는 의심부터 만듭니다. 주차 자리와 수리 시간은
사장님이 정할 수 있는 일이 아닙니다.

**앞날을 약속하지 않고 지금 사실만 적도록 7개 문장을 고쳤습니다.**

```
1개월 이용권은 89,000원이고, 메뉴에 그대로 적어 두었습니다.
기간이 길수록 한 달 값이 내려가니, 얼마나 다니실지부터 정하시는 편이 낫습니다.
주차 공간이 있습니다. 자리가 안 보이면 데스크로 말씀해 주세요.
기구에 이상이 있으면 표시를 붙여 두고 확인합니다.
```

확인할 수 있는 문장이라 **손님도 이쪽을 더 믿습니다.**

AI 지시문에도 같은 금지를 넣었고, 점검표에
**`지킬 수 있을지 모르는 약속이 없다`** 항목을 더했습니다. 걸리면 어느 말이
걸렸는지 그대로 보여 줍니다.

### 무료 답글에도 우리 사실을 한 줄 넣습니다

위 표에서 드러난 진짜 문제입니다. 자동 답글에 **확인된 사실이 하나도 없었습니다.**
`REPLY_TOPIC` 문장은 업종 일반론이라("가격은 부담스럽지 않게 유지하겠습니다")
그것만으로는 어느 헬스장에나 붙는 글이 됩니다.

지금은 메뉴 칸에 적어 두신 것 중 눈에 그려지는 것을 하나 골라 얹습니다.
답글 3개가 **서로 다른 사실**을 말합니다.

```
[1] … 여성전용(우먼존) 24시이용권까지 갖춰 두었습니다. …
[2] … 스미스머신 파워렉 6대도 있으니 편하게 써 보세요. …
[3] … 인바디 무료이용까지 갖춰 두었습니다. …
```

`하루특가`, `5개월 15만원` 같은 **이벤트 문구는 넣지 않습니다** - 답글이 광고가 됩니다.
`보유`, `별도 구비` 같은 꼬리말은 떼고 넣습니다.

### 만든 답글을 우리 잣대로 점검합니다

*"감사 + 매장 홍보 + 재방문"* 세 가지가 들어가야 한다는 건 업계에서 흔히 하는 말인데,
말만 하고 판정은 안 해 줍니다. 저희는 만든 답글을 그 잣대로 실제로 잽니다.

```
첫 번째 답글 점검                                        7 / 7
✅ 감사가 들어갔다      ✅ 우리 강점이 한 가지 들어갔다
✅ 다시 오실 이유가 있다  ✅ 손님이 쓴 말을 되받았다
✅ 길이가 적당하다 (80~400자)  245자
✅ 네이버 금지문자 0개   ✅ 키워드가 들어갔다
```

### AI 지시문 — 재료를 전부 담아서 넘깁니다

AI는 우리 가게를 모릅니다. 그래서 **진단이 알아낸 것을 전부 적어서** 넘깁니다.
API 키가 필요 없고, 쓰시는 AI 채팅에 붙여넣기만 하면 됩니다.

```
- 업체명 / 지역 / 업종 / 이용권 가격 / 목표 키워드 / 보유 시설
- 현재 소개글 상태 · 등록된 대표키워드 · 아직 안 된 항목
- 방문자 리뷰 4,670개 · 평점 4.97점
- 지하철: 봉명역 2번 출구 도보 11분
- 버스정류장: 쌍용패션거리 도보 2분, 열린치과 도보 3분
- 진행 중인 이벤트: 7월은 무료이용
- 손님이 리뷰에서 자주 쓰는 말: 가격(19회), 처음 시작(10회), 혼자 조용히(6회)
- 실제 손님 리뷰 (그대로 인용해도 됩니다): · 혼자 조용히 집중하기 좋은 …
- 상위권이 쓰는데 우리 글에 없는 표현 / 현재 순위
```

소개글 지시문에는 **8단 구성 순서**와 `1,200~1,800자`, 그리고
**네이버 문자 규칙**(이모지·화살표·가운뎃점·큰따옴표·말줄임표·낫표 금지, 마크다운 금지)을
못박아 둡니다. AI가 `·`나 `→`를 쓰면 붙여넣기가 막히기 때문입니다.

지시문은 **8종**입니다 — 소개글 / 대표키워드 / 리뷰 답글 / 소식 글감 /
**짧은 문구 모음** / 블로그 홍보글 / 블로그 정보글 / 개선 계획.
짧은 문구 지시문에는 칸별 글자수 제한을 적고, **문구마다 끝에 `(n자)`를 적으라고**
시킵니다. 그래야 AI가 센 것과 우리가 센 것을 맞춰볼 수 있습니다.

### AI가 써 준 글도 검사합니다

받은 글을 그대로 믿지 않습니다. **어떤 AI로 쓰셨든** 붙여넣으면
우리가 만든 글에 쓰는 잣대를 그대로 들이댑니다.

```
AI 글 점검                                          1 / 10
 ⚠️ 첫 줄이 손님의 고민으로 시작한다
 ⚠️ 5단계가 다 들어갔다
 ⚠️ 글자수 1,200~1,800자              38자
 ⚠️ 네이버 금지문자 0개                · → …
 ⚠️ 추상적 수식어로 시작하지 않는다      발견: 최고의, 프리미엄
```

**금지문자만 고쳐서 복사** 버튼도 있습니다. 구성은 손댈 수 없어도 문자는 우리가 고칩니다.

### 네이버 금지문자 — 추정을 실측으로 깎습니다

네이버는 상세설명에 넣을 수 있는 문자를 제한하지만 **공식 목록을 내놓지 않습니다.**
업계에 도는 "금지문자 N종" 목록은 전부 추정입니다. 그래서 두 겹으로 씁니다.

1. **만들어 드리는 글**에서는 추정 목록에 걸리는 문자를 아예 안 씁니다
   (`·` → `,` / `—` → `-` / `…` → `...` / 굽은 따옴표 → `'`). 손해 볼 일이 없습니다.
2. **사장님 글은 고치라고 하지 않습니다.** 대신 지금 네이버에 등록된 소개글을 같은 잣대로
   검사해서, 걸린 문자가 있으면 이렇게 알려드립니다 —
   *"네이버가 이미 받아준 글이므로 이 문자들은 실제로는 막히지 않습니다."*

등록된 글은 네이버가 통과시킨 글입니다. 거기 있는 문자는 막히지 않는다는 **실측 증거**입니다.
추정으로 겁주는 대신 실측으로 지웁니다.

### 두 화면 — 찾기와 채우기

한 번에 하나만 보입니다. 쓰는 시점이 다르기 때문입니다.

| 메뉴 | 무엇을 하나 | 안에 있는 것 |
|---|---|---|
| 🔍 **대시보드** | 지금 뭐가 비었나 찾는다 | 자동 수집 · 순위 조회 · 상위 3곳 비교 · 체크리스트 · 점수 · 먼저 할 3개 · 저장 내역 |
| ✍️ **채우기 도구** | 그 빈칸에 넣을 문장을 만든다 | 키워드 발굴 · 소개글 · 대표키워드 5개 · 리뷰 답글 3종 · 소식 글감 4주치 · **짧은 문구 모음 7칸** · AI 지시문 8종 |

- 진단이 끝나면 채우기 메뉴에 **주황 점**이 붙고, 결과 맨 아래에 **채우기 도구로 →** 버튼이 생깁니다.
- 진단하기 전에 채우기를 열면 *먼저 진단을 돌리라*고 안내합니다. 채우기 문장은 진단이 읽어온
  업체명·지역·키워드·시설·부족한 항목을 재료로 쓰기 때문에, 진단 없이 만들면 빈칸투성이가 됩니다.
- 마지막에 본 메뉴는 기억해 둡니다. 새로고침해도 그 자리에서 이어집니다.

```
index.html   진단 도구 본체 (단독 실행 가능)
server.js    로컬 서버 — 자동 수집 · 순위 추적 · AI 프록시 (선택)
```

## PC · 휴대폰 함께 쓰기

| | 휴대폰 (단독) | 휴대폰 (PC 켜짐 · 같은 와이파이) | PC |
|---|---|---|---|
| 진단 · 키워드 분석 · 문장 생성 | ✅ | ✅ | ✅ |
| 플레이스 자동 수집 | ❌ | ✅ | ✅ |
| 순위 조회 · 추적 | ❌ | ✅ | ✅ |
| 상위 3곳 경쟁 분석 | ❌ | ✅ | ✅ |

휴대폰 단독으로 안 되는 이유는 네이버가 브라우저의 직접 요청을 막기 때문입니다.
PC의 도우미를 거치면 폰에서도 전부 됩니다 — 설정 방법은 아래 B 항목에 있습니다.

**입력값은 기기마다 자동 저장**됩니다(localStorage). 새로고침해도, 며칠 뒤 다시 열어도 그대로입니다.

**기기를 옮길 때**는 서버를 쓰시면 자동입니다. 서버 없이 쓰실 때만
`저장` 카드의 `서버를 못 쓸 때 - 코드로 다른 기기에 옮기기`를 펼쳐:

1. 보내는 기기 — `코드 만들어 복사` → 카카오톡 '나에게 보내기'에 붙여넣기
2. 받는 기기 — 그 코드를 칸에 붙여넣고 `코드 불러오기`

업체명·지역·키워드·소개글·시설·체크 상태가 전부 그대로 넘어갑니다.
서버 없이 동작하므로 휴대폰↔PC, 집↔매장 어디서든 됩니다.

**다크 테마**는 기기 설정을 따라갑니다. 밤에 폰으로 봐도 눈이 편합니다.

## 휴대폰만으로 쓰기 — 터미널 없이 (권장)

집 PC를 켜 두는 게 번거로우면, 서버를 인터넷에 올려 두면 됩니다.
그러면 폰에서 주소만 열면 은코치처럼 바로 동작합니다.
**설치도 터미널도 필요 없고, 폰 브라우저에서 탭 몇 번이면 끝납니다.**

1. 폰에서 [render.com](https://render.com) → **Get Started** → **GitHub 로 로그인**
2. **New +** → **Blueprint** → 이 저장소(`development_place`) 선택 →
   브랜치를 `claude/webpage-dev-analysis-1rmgca` 로 지정 → **Apply**
   (저장소 안의 `render.yaml` 을 읽어 알아서 띄웁니다. 고를 것이 없습니다.)
3. 배포가 끝나면 `https://gym-place-check-xxxx.onrender.com` 같은 주소가 나옵니다
4. 대시보드 → **Environment** → `ACCESS_KEY` 값을 복사
5. 폰 브라우저에서 **`https://그-주소/#k=복사한값`** 을 열고 **북마크**
   → 키가 폰에 저장돼서 다음부터는 북마크만 누르면 됩니다

> **무료 요금제는 15분쯤 안 쓰면 서버가 잠듭니다.**
> 다시 열 때 첫 화면이 1분쯤 걸리고, 그동안 "서버를 깨우는 중입니다" 라고 나옵니다.
> 두 번째부터는 바로 뜹니다.

#### 접근 키를 바꿨거나, 새 기기에서 열었을 때

화면 위쪽에 **🔑 접근 키를 넣어 주세요** 칸이 나옵니다.
대시보드 → **Environment** → `ACCESS_KEY` 값을 복사해 붙여넣고 **연결**을 누르면 됩니다.
`#k=` 붙은 주소를 다시 찾을 필요가 없습니다.

- 값이 틀리면 **"이 값으로는 열리지 않습니다"** 라고 그 자리에서 알려 줍니다. 틀린 값은 저장하지 않습니다.
- 이 기기에 **예전 키**가 남아 있으면 **"저장된 접근 키가 서버와 다릅니다"** 라고 나옵니다.
  키를 바꾸신 뒤 폰이 안 되는 경우가 여기입니다.

> **왜 이게 따로 필요한가** — 서버 생사 확인 경로(`/api/health`)는 키 없이 열려 있습니다.
> 렌더의 점검기가 여기서 401을 받으면 서버가 죽은 줄 알고 트래픽을 끊기 때문입니다.
> 그래서 **키가 틀려도 화면은 "서버 연결됨"으로 보일 수 있었고**, 정작 수집·순위·AI 는
> 전부 401 로 실패했습니다. 지금은 잠긴 경로를 한 번 더 두드려서 확인한 뒤에
> "연결됨"을 표시합니다.

> **먼저 알아두실 것** — 네이버가 데이터센터에서 오는 요청을 막을 수 있습니다.
> 집 PC(가정용 인터넷)에서는 정상 응답(HTTP 200)이 확인됐지만, 클라우드에서도
> 같을지는 올려 봐야 압니다. 막히면 수집 결과가 비고, 화면이 그렇게 알려 줍니다.
> 그때는 아래 B(집 PC) 방식으로 돌아가면 됩니다. **올려 보는 데 드는 비용은 없습니다.**

`ANTHROPIC_API_KEY` 를 Environment 에 넣으면 AI 문장 생성도 폰에서 됩니다.
안 넣으면 그 기능만 꺼지고 나머지는 전부 동작합니다.

## 두 가지 실행 방법

### A. 수동 모드 — 설치 없음

`index.html`을 더블클릭해서 브라우저로 엽니다. 휴대폰에서도 그대로 씁니다.
진단·키워드 분석·문장 생성은 전부 됩니다.

### B. 서버 모드 — 자동 수집 + 순위 추적 + 경쟁 분석

**더블클릭으로 실행합니다. 명령어를 칠 필요 없습니다.**

| 운영체제 | 실행할 파일 |
|---|---|
| 윈도우 | `start.bat` |
| 맥 | `start.command` (처음 한 번은 우클릭 → 열기) |

Node.js 18 이상만 있으면 됩니다(`https://nodejs.org`에서 LTS 설치).
**npm install 불필요** — 외부 의존성이 하나도 없습니다.
브라우저가 알아서 열리고, 페이지 상단에 `자동 수집 · 순위 추적` 패널이 나타납니다.

터미널을 쓰신다면 `node server.js` 도 동일합니다.

#### 휴대폰에서도 쓰기

PC에서 서버를 켜면 화면과 터미널에 **휴대폰용 주소**가 나옵니다.

```
휴대폰에서      http://192.168.0.12:5173/#k=xxxxxxxx
```

같은 와이파이에 연결한 뒤 휴대폰 브라우저로 한 번 접속해 **북마크**해 두세요.
그 뒤로는 북마크만 누르면 폰에서도 자동 수집·순위 조회·경쟁 분석이 전부 됩니다.
(PC가 켜져 있고 같은 와이파이일 때)

주소 뒤의 `#k=...`는 **접근 키**입니다. 서버를 0.0.0.0으로 열면 같은 와이파이의
다른 기기도 접근할 수 있어서, 외부 기기 요청에만 키를 요구합니다.
키는 `data/access-key.txt`에 저장되므로 서버를 다시 켜도 북마크가 계속 동작합니다.
휴대폰 접속이 필요 없다면 `HOST=127.0.0.1 node server.js`로 이 PC만 열 수 있습니다.

#### PC 켤 때 자동 실행 (선택)

**윈도우** — `Win+R` → `shell:startup` → 열린 폴더에 `start.bat` 바로가기를 넣습니다.

**맥** — 시스템 설정 → 일반 → 로그인 항목 → `+` 로 `start.command` 추가.

#### 순위 자동 기록 (선택)

브라우저를 열지 않고 순위만 기록합니다. 스케줄러에 걸어두면 추이가 알아서 쌓입니다.

```bash
node server.js --track "강남역 헬스장" "https://map.naver.com/p/entry/place/1234567890"
```

- 맥/리눅스 — `crontab -e` 에 `0 9 * * * cd /경로 && node server.js --track "키워드" "URL"`
- 윈도우 — 작업 스케줄러에서 매일 실행 등록

기록은 `data/rank-history.json`에 쌓이고, 페이지의 순위 조회에서 ▲▼ 변동으로 보입니다.

| 기능 | 설명 |
|---|---|
| **정보 자동 수집** | **플레이스 주소 한 줄만 넣으면 1·2·3단계가 거의 다 채워집니다** |
| 순위 조회 | 목표 키워드로 검색했을 때 내 가게가 몇 위인지 조회합니다 |
| 순위 추적 | 조회할 때마다 `data/rank-history.json`에 기록되고, 직전 대비 ▲▼ 변동을 표시합니다 |
| **상위 3곳 분석** | **상위권이 왜 뜨는지 분석하고, 우리가 뭘 해야 하는지 뽑아냅니다** |
| AI 프록시 | API 키가 서버에만 있고 브라우저로 내려오지 않습니다 |

### 상위 3곳 분석 — 이 도구의 핵심

목표 키워드로 검색해 **상위 3곳을 실제로 수집·비교**합니다.

**1. 지표 비교 + 3위 진입선**

| 지표 | 우리 | 1위 | 2위 | 3위 | 3위 진입선 |
|---|---:|---:|---:|---:|---|
| 방문자 리뷰 | 41개 | 312 | 268 | 190 | **149개 부족** |
| 사진 | 12장 | 88 | 64 | 52 | **40장 부족** |

상위 3곳 중 **가장 낮은 값**이 곧 3위 진입선입니다. 막연한 "많이 채우세요"가 아니라 숫자로 나옵니다.

**2. 상위권이 공통으로 쓰는데 우리에겐 없는 표현**

헬스장 도메인 어휘 사전(시설·프로그램·운영조건·대상·기구·신뢰 6개 범주)으로
상위권 소개글을 훑어, **2곳 이상이 쓰는데 우리에겐 없는 표현**을 뽑습니다.

> 누락: 무료주차(3/3곳), 샤워실(3/3곳), 24시간(3/3곳), 무료체험(3/3곳), PT, 락커, 운동복 …

`무료주차`가 잡히면 `주차`는 자동으로 흡수해 목록이 부풀지 않습니다.

**3. 거리 추정**

네이버의 실제 검색 좌표는 알 수 없지만, **상위권이 몰려 있는 지점이 그 키워드의 중심**입니다.
상위 3곳 좌표의 중심을 검색 중심으로 잡고 우리 거리를 잽니다.

**4. 결론 — 반드시 3개로 나눕니다**

여기가 이 기능의 핵심입니다. 격차를 뭉뚱그리면 실행할 수 없는 목록이 됩니다.

| 분류 | 내용 |
|---|---|
| 🟢 오늘 할 수 있는 것 | 소개글 길이, 누락 표현 추가, 사진 업로드 |
| 🟡 시간이 걸리는 것 | 리뷰·저장·평점 — 몇 주~몇 달. 구매는 제재 대상 |
| ⚪ 바꿀 수 없는 것 | 거리. 이 경우 **다른 키워드로 목표를 바꾸라고** 조언합니다 |

AI를 쓰려면 키를 환경변수로 넣고 서버를 켜세요:

```bash
ANTHROPIC_API_KEY=sk-ant-... node server.js
```

## 이 점수의 근거 — 어디까지가 사실인가

네이버는 순위 계산식을 공개하지 않는다. 그래서 근거의 세기를 나눠 둔다.

| 구분 | 내용 | 근거 |
|---|---|---|
| 3축 구조 | 적합도 · 인기도 · 거리 | 네이버가 밝힌 취지 (연관도·이용자 반응·거리) |
| 45 / 40 / 15 | 축별 배점 | **추정.** 네이버는 비중을 공개한 적이 없다 |
| 항목 존재 여부 | 카테고리·영업시간·편의시설·가격·대표키워드·소개글·사진·예약 | 스마트플레이스 가이드가 채우라고 안내하는 것들 |
| 항목별 숫자 기준 | 사진 30장, 리뷰 50개, 답글 90% 등 | **추정.** 방향은 업계에서 반복 관찰되나 숫자는 임의 |
| 키워드 매칭 8점 | 목표 키워드 × 소개글 실제 대조 | **계산.** 가정이 없다 |

### 추정을 실측으로 바꾸는 장치 — 기준 보정

`상위 3곳 분석`을 돌리면, 그 키워드에서 실제로 3위 안에 든 가게들의 숫자가 나온다.
그 최저값(진입선)으로 추정 기준을 갈아치운다.

```
보정 전: 사진 30장 이상        ← 내가 정한 숫자
보정 후: 사진 52장 이상        ← "강남역 헬스장" 상위 3곳 중 최저값
```

지역·업종·경쟁 강도가 다 다르므로 전국 공통 숫자보다 그 키워드의 실제 진입선이 맞다.
보정된 항목에는 `기준 52장` 배지가 붙고, 눌러 보면 상위 3곳의 실제 값이 나온다.
보정 전에는 화면에 "이 숫자는 추정값"이라고 밝힌다.

### 그래도 남는 한계

점수가 오르는 것과 순위가 오르는 것은 다르다. 이 점수는 **채울 수 있는 것을 채웠는가**의
진척도이고, 네이버가 매길 점수가 아니다. 실제 인과는 `순위 기록`과 `개선 기록`으로
사장님 가게에서 확인하는 수밖에 없다.

### 주소 한 줄 → 나머지 자동

서버가 켜져 있으면 `정보 자동 수집` 버튼 하나로 이만큼이 채워집니다.

| 단계 | 자동으로 채워지는 것 | 근거 |
|---|---|---|
| 1단계 | 업체명 | 수집값 |
| | **지역** | 등록된 대표키워드의 역명 → 없으면 주소(동 > 구 > 시) |
| | **주력 업종** | 카테고리 문자열 판별 |
| | **1개월 가격** | 메뉴 중 "1개월/한달" 항목 |
| 2단계 | 소개글 | 수집값 |
| | **대표키워드** | 등록된 키워드 목록 |
| | **목표 키워드** | 등록된 대표키워드를 그대로 (없으면 지역·업종으로 추측) |
| 3단계 | 체크 12개 | 아래 자동 판정 표 참조 |

**목표 키워드는 등록된 대표키워드를 최우선으로 씁니다.**
주소는 "어디에 있는가"일 뿐이고, 대표키워드는 "어디로 검색되고 싶은가"입니다.
주소가 역삼동이어도 대표키워드가 `강남역헬스장`이면 목표는 강남역입니다.

**이미 손으로 입력한 값은 덮어쓰지 않습니다.** 빈 칸만 채웁니다.
무엇을 어떤 근거로 채웠는지 화면에 남으므로, 틀렸으면 그 자리에서 고치면 됩니다.

### 22개 중 16개가 자동, 6개만 손으로

| 판정 방식 | 개수 | 항목 |
|---|---:|---|
| **입력값으로 계산** | 4 | 키워드 매칭, 소개글 길이, 대표키워드 수, 업체명 스터핑 |
| **수집값으로 판정** (서버 실행 시) | 12 | 사진 수, 리뷰 수, 블로그 리뷰, 저장 수, 예약·톡톡, 홈페이지, 영업시간, 가격, 편의시설, 사업자 인증, 카테고리, 소식 |
| **직접 확인** | 6 | 대표사진 내용, 구역별 사진, 사진 최신성, 리뷰 답글률, 최근 리뷰, 지도 핀 |

자동 판정된 항목은 체크박스가 알아서 켜지고 `자동` 배지가 붙습니다.
배지에 마우스를 올리면 **무슨 근거로 판정했는지**(예: "사진 46장") 나옵니다. 직접 고쳐도 됩니다.

**근거가 없으면 판정하지 않습니다.** 수집에 실패했거나 사진을 봐야 아는 항목은
추측으로 채우지 않고 "직접 확인"으로 남깁니다. 추측으로 채우면 점수가 거짓이 되기 때문입니다.

남은 6개가 자동화되지 않는 이유:

- 대표사진이 시설 전경인지, 어느 구역 사진인지 → 사진을 봐야 압니다
- 사진 업로드 시점 → 공개 정보에 없습니다
- 리뷰별 답글 유무, 리뷰 작성일 → 리뷰를 하나씩 열어야 합니다
- 지도 핀이 실제 출입구인지 → 물리적으로 확인해야 합니다

### 수집해도 점수가 안 오르는 이유를 화면에 적습니다

점수판 아래에 이렇게 갈라서 나옵니다.

```
수집으로 채워지는 점수          23 / 23점 — 이미 만점입니다
사장님이 체크해야 오르는 점수    16 / 77점

네이버에서 가져올 수 있는 항목은 이미 다 만점입니다.
수집을 다시 눌러도 총점은 움직이지 않습니다.
남은 61점은 아래 ✅ 할 일에서 이미 하고 계신 것에 체크하시면 바로 오릅니다.
```

**리뷰가 4,673개든 10만 개든 "50개 이상" 기준이라 배점은 같습니다.**
자동 항목이 만점이면 수집을 몇 번을 눌러도 총점은 그대로입니다.
이걸 안 적어 둬서 "수집이 안 먹는다"로 읽힌 적이 있어 화면에 넣었습니다.

### 소개글 자리에 네이버 광고 문구가 들어오던 문제

네이버는 아폴로 캐시에 **인자를 받는 필드를 이름 뒤에 인자까지 붙여** 저장합니다.

```
description({"source":["shopWindow","jto"]})   ← 사장님이 쓴 소개글 1,947자
businessTools.tools[].description               ← 네이버가 파는 서비스 광고 20자
```

`description` 이라는 이름만 비교하면 **앞의 것을 못 알아보고** 뒤의 것을 집어 왔습니다.
실제로 소개글 자리에 `"전화를 대신 받고 응대까지 해드려요!"` 가 들어왔습니다.
그 상태로 진단하면 적합도가 통째로 틀어집니다.

지금은 이름을 비교하기 전에 **괄호 뒤를 잘라냅니다.** 리뷰 수·사진 수·전화번호처럼
인자가 붙어 오던 다른 값들도 같이 잡히게 됐습니다.
`businessTools` 같은 **광고 자리는 소개글 후보에서 아예 제외**합니다.

### 적합도는 체크가 아니라 계산입니다

목표 키워드와 소개글을 넣으면:

- 키워드가 소개글·업체명·대표키워드에 실제로 있는지 **토큰 단위로 매칭**
- 구문 전체 매칭 / 부분 매칭 / 약한 매칭 / 매칭 없음 판정
- 단어별 출현 횟수와 위치 표시
- **과다 반복 감지** — 12회 이상이거나 밀도 6% 초과(300자 이상일 때)면 어뷰징 경고
- **업체명 키워드 스터핑 감지** — 지역·업종어가 2개 이상 박혀 있으면 경고

### 개선 기록 — 내 가게의 실전 데이터를 쌓습니다

이 도구의 약점은 **실전 컨설팅 사례가 없다**는 것입니다.
항목과 배점은 공개된 노출 원리에서 나온 추정이지, 수백 건의 검증을 거친 값이 아닙니다.

남의 사례를 흉내 낼 수는 없으니, **내 가게 데이터를 직접 쌓는 장치**를 넣었습니다.

1. 할 일을 처리하면 `완료`를 눌러 기록
2. 순위를 조회하면 그 기록과 시간순으로 겹쳐 표시

```
7/29  이용권·PT 가격을 공개했다 완료
7/29  "강남역 헬스장" 12위
8/02  사진이 30장 이상 등록되어 있다 완료
8/05  "강남역 헬스장" 8위  ▲ 4
```

**인과로 단정하지 않습니다.** 경쟁사 변화·계절 같은 다른 요인도 순위를 움직입니다.
다만 같은 작업이 여러 번 순위 상승 앞에 나온다면 그건 신호로 볼 만합니다.

기록은 브라우저에 저장되고(서버 없이 휴대폰에서도 기록됩니다),
기기 간 이어쓰기 코드에 함께 담겨 옮겨집니다.

### 병목 축 진단

세 축 중 가장 낮은 축을 지목하고, 왜 그 축이 발목을 잡는지 인과 사슬로 보여줍니다.

```
정보 채우기 → 검색 후보 진입 → 거리 필터 통과 → 노출 → 클릭·체류·저장 → 순위 상승
```

세 축이 모두 80% 이상이면 병목 대신 "뚜렷한 병목 없음"으로 안내합니다.

## 네이버 응답이 깨졌을 때

네이버는 공개 API가 없고 내부 응답 구조를 예고 없이 바꿉니다.
그래서 이 서버는 **경로를 고정해 파싱하지 않고**, 여러 엔드포인트를 순서대로 시도한 뒤
응답 트리 전체를 훑어 **필드 이름으로 값을 주워담습니다.** 구조가 바뀌어도 잘 버팁니다.

그래도 깨지면 점검 명령으로 원인을 확인하세요:

```bash
node server.js --probe "강남역 헬스장" "https://map.naver.com/p/entry/place/1234567890"
```

출력은 `[0] 플레이스 ID 확인` → `[1] 플레이스 정보 수집` → `[2] 순위 조회` 순서입니다.
`[0]`에서 멈추면 주소 문제, `[1]`·`[2]`에서 멈추면 네이버 응답 문제입니다.

`[1]`이나 `[2]`가 실패했다면, 응답 안에 무엇이 들어있는지 지문을 뜹니다:

```bash
node server.js --dump "강남역 헬스장" "https://map.naver.com/p/entry/place/1234567890"
```

엔드포인트마다 HTTP 상태·본문 길이·`window.__변수__` 이름·`<script id>`·
차단 문구 여부·**필드 이름이 본문에 원문으로 있는지**를 출력합니다.
마지막 항목이 판단의 핵심입니다 — 필드 이름이 보이면 컨테이너만 못 찾는 것이고,
안 보이면 그 응답에는 데이터가 애초에 없습니다(별도 API 호출로 그려지는 페이지).

본문 전문은 `data/dump/` 에 저장됩니다(`.gitignore` 처리됨).

> 키워드와 URL 사이에 **공백을 반드시** 두세요. `"키워드""URL"` 처럼 붙여 쓰면
> PowerShell이 둘을 한 인자로 합칩니다. (붙여 써도 알아서 갈라내지만 경고가 뜹니다.)
>
> `naver.me` 단축 링크도 됩니다. 리다이렉트를 따라가 실제 번호를 찾습니다.
> 단축 링크가 열리지 않으면 지도 주소창의 긴 주소를 쓰세요.

API 엔드포인트:

| 경로 | 설명 |
|---|---|
| `/api/place?url=` | 플레이스 정보 수집 |
| `/api/rank?keyword=&url=` | 순위 조회 (자동 기록) |
| `/api/competitors?keyword=&url=&top=3` | 상위 N곳 경쟁 분석 |
| `/api/history?keyword=` | 순위 기록 조회 |
| `/api/ai` | Claude 프록시 (POST) |

어떤 엔드포인트를 시도했고 각각 어떻게 실패했는지 전부 출력됩니다.
그 출력을 그대로 알려주시면 파서를 맞출 수 있습니다.

> **참고** — 개발 환경의 네트워크 정책상 네이버 접속이 차단되어 있어,
> 수집·순위 로직은 응답을 흉내 낸 테스트로만 검증했습니다.
> 실제 네이버 응답에 대한 첫 검증은 사장님 PC에서 위 `--probe`로 하셔야 합니다.

## 이 도구가 하는 일과 못 하는 일

**하는 일** — 통제 가능한 항목의 누락을 찾아냅니다.
매일 보느라 안 보이던 빈칸을 남의 눈으로 훑어주는 것, 그리고 목표 키워드가
실제로 매칭되는지 계산해주는 것이 핵심 가치입니다.

**못 하는 일** — 네이버 점수를 알려주지 못합니다.
네이버는 순위 알고리즘을 공개하지 않습니다. 여기 나오는 점수는 네이버 점수가 아니라
**공개된 노출 원리를 바탕으로 만든 체크리스트의 점수**입니다.
적합도는 입력값으로 실제 계산하지만, 인기도·거리는 자가 체크 기반입니다.

정보를 채운다고 순위가 오르는 게 아닙니다.
**채워야 노출될 자격이 생기고 → 노출돼야 클릭이 생기고 → 클릭이 쌓여야 순위가 오릅니다.**
이 도구는 그 출발선에 서게 해주는 역할입니다.

리뷰·저장수 구매 같은 어뷰징은 네이버가 갈수록 정교하게 잡아냅니다. 권하지 않습니다.
